一、模組概述與定位

ERMM 財務模組是整個 ERP 系統的價值終點，貫穿「接單 → 採購 → 生產 → 出貨 → 收付款 → 財務報表」完整價值鏈。本模組負責：

  • 應收應付管理 (AR/AP) — 從銷售訂單與採購訂單自動彙算應收/應付帳款
  • 付款與票據管理 — 應付明細登錄、付款沖帳、支票/轉帳票據管理
  • 銀行貸款管理 — 銀行帳戶、貸款合約、利息計算、匯兌損益
  • 財務三大報表 — 資產負債表、損益表(PL)、現金流量摘要
  • 稅務與風險控制 — 稅務檢核項目、財務風險控管、匯率管理
  • 財務分析圖表 — AR/AP 趨勢圖、現金日明細、多維度管道圖
模組定位：財務模組既是資料消費者（接收業務模組的 SO/PO/庫存資料），也是決策輸出者（產生報表供管理層決策）。透過 batch_ARAP_upd.asp 批次程式實現與業務模組的資料同步。

三、子系統功能拆解

3.1應收應付子系統 (AR/AP)
從銷售訂單 (SO) 彙算應收帳款 AR_amt = Σ(unit_price × dn_qty)，從採購訂單 (PO) 彙算應付帳款 AP_amt = Σ(po_amount + vat_amt)，按 YYYY_MM 月度匯總寫入 ERMM_ARAP_detail 表，並以 FusionCharts 渲染趨勢圖。
3.2付款/票據子系統
應付明細 (pay_detail 表) 記錄每筆應付帳款：供應商、費用類型、發票日期/號碼、金額、幣別、應付日期、付款日期。支援新增/修改/刪除/查詢/Excel 匯出。支票管理記錄現金支票/轉帳支票的開票明細。
3.3銀行貸款子系統
MGM_bank_loan_details 表記錄銀行帳戶與貸款合約，支援存款/貸款/還款三類。自動計算下次利息日 (next_paydate = dateadd(MM, pay_terms, last_paydate)) 與應計天數 (pay_days = DATEDIFF(dd, GETDATE(), next_paydate))。多幣別貸款支援匯兌損益計算。
3.4財務報表子系統
MGM_finance_summary 為核心報表資料表，按月 (YYYY_MM) 儲存完整資產負債與損益科目。系統自動為當年度 12 個月預建記錄，供人工填報或批次匯入。支援當月/上月比較、Excel 匯出。
3.5稅務/風險子系統
稅務檢核項目管理 (STD_finance_tax_check_items_mgmt) 與三級風險控制 (STD_finance_risk_control3)，提供財務合規檢核與風險預警能力。

模型 1：Z-Score (Altman 1968, 上市公司)

-- 5 個變數 ZX1 = (LQ_asset_amt - LQ_debet_amt) / ttl_asset_amt 流動淨值/總資產 ZX2 = retained_income_amt / ttl_asset_amt 保留盈餘/總資產 ZX3 = (pretax_profit_amt + interest_amt) / ttl_asset_amt (稅前淨利+利息)/總資產 ZX4 = stockholder_amt / ttl_debet_amt 股東權益/總負債 ZX5 = sale_amt / ttl_asset_amt 銷貨/總資產 Z = 1.2×ZX1 + 1.4×ZX2 + 3.3×ZX3 + 0.6×ZX4 + 0.999×ZX5

模型 2：Z2-Score (Altman Z', 私人公司)

Z2_X2 = accumulated_amt / ttl_asset_amt 累積盈餘/總資產 Z2 = 0.717×ZX1 + 0.847×Z2_X2 + 3.107×ZX3 + 0.420×ZX4 + 0.998×ZX5

模型 3：Z3-Score (Altman Z'', 非製造業)

Z3_X3 = (pretax_profit_amt + depreciation_amt) / ttl_asset_amt (稅前淨利+折舊)/總資產 Z3 = 6.56×ZX1 + 3.26×Z3_X2 + 6.72×Z3_X3 + 1.05×ZX4 判定標準： Z < 1.23 → 破產區 (紅燈) 1.23 ≤ Z < 2.9 → 灰色地帶 (黃燈) Z ≥ 2.9 → 安全區 (綠燈)

模型 4：BZ 破產概率模型

BZ_X1 = (pretax_profit_amt + depreciation_amt) / LQ_debet_amt BZ_X2 = pretax_profit_amt / (LQ_asset_amt - LQ_debet_amt) BZ_X3 = stockholder_amt / ttl_debet_amt BZ_X4 = FX_asset_amt / ttl_debet_amt BZ_X5 = (LQ_asset_amt - LQ_debet_amt) / ttl_asset_amt BZ = BZ_X1 + BZ_X2 + BZ_X3 + BZ_X4 + BZ_X5

模型 5：JZ 營運能力模型

ZA = LQ_asset_amt / LQ_debet_amt 流動比率 ZB = (LQ_asset_amt - stock_all_amt) / LQ_debet_amt 速動比率 ZC = LQ_debet_amt / (ttl_asset_amt - debet_amt) 流動負債/股東權益 ZD = debet_amt / (ttl_asset_amt - debet_amt) 總負債/股東權益 JZ = ZA + ZB - ZC - ZD 值越大營運能力越強

八、權限與安全控制

8.1 登入權限檢查

所有財務頁面透過 <!--#include file="../public/config.asp"--> 進入時檢查 Session：

if session("user_name")="" then → 跳轉 login.asp (登入逾時) if session("finance")<>"Y" → 無財務模組權限 leader_user.system="Y" → 系統管理者 (全部權限) leader_user.account="E" → 帳務專員 (可匯出 Excel)

8.2 操作權限分級

權限等級判斷條件可執行操作
系統管理者leader_user.system="Y"新增/修改/刪除/匯出 全部
帳務專員leader_user.account="E"新增/修改/刪除/匯出
一般使用者其他僅查詢 (匯出按鈕 disabled)

8.3 輸入驗證

pay_add.asp 前端 JavaScript 驗證必填欄位：

  • 供應商名稱 (supplier_name) 不可為空
  • 應付日期 (should_date) 不可為空
  • 發票日期 (invoice_date) 不可為空
  • 金額 (amount) 不可為空
  • 幣別 (currency_ab) 不可為空
  • 發票號碼 (invoice_num) 不可為空
  • 費用內容 (expense_content) 不可為空

8.4 SQL 安全

注意：現有程式使用字串拼接方式組裝 SQL (sql = "select * from pay_detail where uid='"&request("radio")&"'")，存在 SQL Injection 風險。建議開發新功能時改用參數化查詢 (ADODB.Command + Parameters)。

9.3 擴展新財務報表的步驟

  1. 在 MGM_finance_summary 表新增科目欄位 (ALTER TABLE ADD)
  2. 在 STD_finance_summary.asp 讀取新欄位並顯示表單
  3. 在 STD_finance_balance_sheet.asp 或 STD_finance_PL_table.asp 加入計算邏輯
  4. 在 cams_xwebpage 註冊新頁面 (seq_system 跨號 8500 系列)
  5. 透過 cams_xusers_webpage 授權給使用者

9.4 批次作業擴展

新增財務批次計算時，遵循 batch_ARAP_upd.asp 模式：

  • 以 GETDATE() 產生 batch_id 作為時間戳
  • 先 SELECT 檢查記錄是否存在，再決定 INSERT 或 UPDATE
  • 處理 NULL 值：UPDATE ... SET amt='0' WHERE amt IS NULL
  • 完成後 alert 顯示處理筆數
  • 在 cams_global_codes 設定對應截止日期 (CUTOFF)
