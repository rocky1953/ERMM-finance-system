1. 系統總覽與架構

ERMM 財務模組管理系統是一套以 Node.js + Express 為後端、MySQL 8 為資料庫、純前端 JavaScript + Chart.js 為展示層的財務管理平台，覆蓋從 ERP 原始單據匯入、日常財務作業、三大報表生成、風險預警計算到損益平衡分析的全流程。

📊

財務儀表板

KPI 卡片、月度損益柱狀圖（可點擊鑽取發票明細）、風險燈號面板（Z-Score 可點擊查看說明）

🛒

ERP 原始單據

採購單 PO、銷售訂單 SO、送貨單 DN、PO 暫存區，支援批次管線七步加工

💵

日常作業

現金日記帳、發票管理（進銷項）、付款明細、票據管理、銀行貸款、應收應付彙算

📋

三大報表

資產負債表、損益表（PL）、現金流量表，支援 Excel 匯出

⚠️

風險預警

Altman Z-Score / Z2 / Z3 三模型、流動比率、負債比、ROE / ROA 燈號面板

⚖️

BEP 損益平衡

材料成本 7 項鑽取、變動費用 / 固定成本明細、門檻值勾稽核驗、即時重算

🎯

KPI 指標

YG001–YG004 四大模型，涵蓋預警指標、指標管理、報表異常甄別、預測模型分析

🌐

三語國際化

2. 安裝與啟動

2.1 環境需求

軟體版本用途
Node.js18+（建議 20 LTS）後端服務 + 離線匯入腳本
MySQL8.x（utf8mb4）資料庫 ERMM_db
瀏覽器Chrome / Edge 最新版前端操作
Git2.x版本控制

2.2 首次安裝

# 1. 克隆倉庫
git clone https://github.com/rocky1953/ERMM-finance-system.git e:\finance
cd e:\finance

# 2. 安裝 Node 依賴
npm.cmd install

# 3. 建立 MySQL 資料庫
mysql -uroot -p -e "CREATE DATABASE ERMM_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 4. 建表
mysql -uroot -p ERMM_db < database\schema.sql
# 或跑 migrations
mysql -uroot -p ERMM_db -e "source migrations/run_all.sql"

# 5. 建立 BEP 門檻表
node database/create_bep.js

# 6. 設定 .env（參見下方）
# 7. 啟動服務
node app.js

2.3 環境設定檔 .env

鍵說明範例值
PORTExpress 監聽埠3008
DB_HOSTMySQL 位址127.0.0.1
DB_PORTMySQL 埠3306
DB_USERDB 帳號root
DB_PASSWORDDB 密碼（你的密碼）
DB_NAME資料庫名ERMM_db
JWT_SECRET登入簽章隨機長字串

2.4 啟動 / 停止 / 驗證

# 啟動
cd e:\finance
node app.js

# 驗證（另一終端）
Invoke-RestMethod http://localhost:3008/api/health -UseBasicParsing
# 回傳 success=true 即正常

# 停止（背景任務）
netstat -ano | findstr ':3008' | findstr LISTENING
taskkill /F /PID <查到的PID>
啟動後打開瀏覽器訪問 http://localhost:3008 即可使用全部功能。

4. 財務儀表板（Dashboard）

儀表板是系統首頁，彙整當前公司+月份的核心財務指標，分為四個區塊：

4.1 KPI 卡片區

頂部一排 KPI 卡片，即時顯示當月關鍵數據（銷貨收入、銷貨成本、營業毛利、淨利等），數據來自 GET /api/summary。

4.2 月度損益概況（柱狀圖 — 可鑽取）NEW

Chart.js 柱狀圖，6 根柱子分別為：銷貨收入、銷貨成本、營業毛利、營業利益、營業利潤、淨利。

鑽取操作：點擊銷貨收入（藍色柱）→ 彈出銷項發票（AR）明細視窗；點擊銷貨成本（紅色柱）→ 彈出進項發票（AP）明細視窗。明細表含日期、發票號、客戶/供應商、未稅金額、稅額、付款狀態、合計行與筆數。其餘 4 根柱子不可點擊。

彈窗支援四種關閉方式：

  • 右上角 ✕ 按鈕
  • 底部「關閉」按鈕
  • 點擊遮罩（彈窗外部區域）
  • 按鍵盤 Esc

4.3 風險燈號面板（Z-Score — 可點擊說明）NEW

顯示 Altman Z-Score 及衍生指標，依分數著色：

燈號Z 值範圍風險等級說明
🟢 綠燈Z ≥ 2.9安全破產風險低，財務體質健全
🟡 黃燈1.23 ≤ Z < 2.9灰色地帶存在財務危機疑慮，應持續關注
🔴 紅燈Z < 1.23破產區破產風險高，須儘速改善財務結構
點擊操作：點擊「Z-Score 風險等級」卡片 → 彈出說明視窗，包含：
  • 模型簡介（Altman Z-Score 用途）
  • 當前 Z 值大數字 + 燈號徽章
  • 三風險區間對照表（當前所在區間高亮+色條標記）
  • 計算公式：Z = 1.2·X1 + 1.4·X2 + 3.3·X3 + 0.6·X4 + 0.999·X5
  • X1–X5 五項變數表（權數 / 財務含義 / 本月實際值）
  • Z2-Score（私人公司模型）、Z3-Score（非製造業模型）分數卡片

4.4 資產負債摘要

底部展示流動資產、非流動資產、流動負債、長期負債等彙總數據，與三大報表中的資產負債表連動。

5. ERP 原始單據

5.1 採購單 PO（po）

管理正式採購訂單，由批次管線 Step1 從 PO 暫存區加工產出。頁面支援查詢（依公司+月份篩選）、檢視明細。PO 狀態值為中文（如「未審核」「審核通過」），前端以 t() 翻譯顯示。

5.2 銷售訂單 SO（so）

管理客戶銷售訂單，記錄訂單號、客戶、金額、幣別、匯率、交期等。可由頁面新增或 API 批量匯入。

5.3 送貨單 DN（dn）

記錄出貨/交貨單據，與 SO 關聯，記錄送貨日期、數量、狀態。

5.4 PO 暫存（tempPo）

第三方 ERP 採購單落地區。資料先進暫存，經批次管線 Step1 清洗加工後轉為正式 PO。支援按 batch_id 批量清除。

批次管線流程：PO 暫存 → Step1 轉正式 PO → Step2 加工本幣金額 → Step3 供應商彙算 → Step5 庫存日結算 → Step6 AR/AP 彙算 → Step7 財務摘要重算。詳見第 10 節。

6. 日常作業

6.1 現金日記帳（cash）

記錄每筆現金收支，欄位：DB_CR（DR=收入 / CR=支出）、amt_type（收支類型如銷貨收入/原料採購）、sub_amt（金額）。系統自動由 DB_CR + sub_amt 推導 in_amt / out_amt，並按日期累加計算 balance_amt（累計餘額）。

頁面頂部顯示四張彙總卡片：總收入（DR 合計）、總支出（CR 合計）、淨額（收入-支出）、餘額（累計淨額）。

6.2 發票管理（invoice）

管理進銷項發票，TX_type：AR=銷項（收入）、AP=進項（成本）。支援 POST /genAR、POST /genAP 自動產生應收/應付發票。頁面篩選可依公司、月份、發票類型、客戶、發票號。

儀表板損益柱狀圖鑽取取的正是此表的 AR / AP 資料。

6.3 付款明細（pay）

記錄付款執行明細，支援 POST /:uid/pay 註記已付款，狀態分為 paid / unpaid。

6.4 票據管理（check）

管理應收/應付票據（支票），記錄開票日、到期日、金額、狀態。支援 POST /:uid/clear 兌現操作。

6.5 銀行貸款（bank）

管理銀行存貸款明細，bu_no + loan_id 為必填聯合鍵。支援 POST /recalc 重算餘額。

6.6 應收應付（arap）

月底 AR/AP 彙總，可由批次管線 Step6 自動產出，或 POST /recalc 手動觸發。

7. 財務分析

7.1 財務摘要（summary）

核心樞紐頁面，200+ 欄位涵蓋資產、負債、權益、收入、成本、費用等全量財務數據。由批次管線 Step7 重算三大報表。支援 POST /calcPL（損益計算）和 POST /addon（附加計算）。

7.2 三大報表（report）

以頁籤切換顯示三張報表：

  • 資產負債表（Balance Sheet）— 資產 = 負債 + 股東權益
  • 損益表（P&L）— 收入 - 成本 - 費用 = 淨利
  • 現金流量表（Cash Flow）— 間接法，分營運/投資/籌資

每張報表支援 Excel 匯出（.xlsx）：

報表匯出路由
資產負債表/api/report/export/balance-sheet.xlsx
損益表/api/report/export/pl-table.xlsx
現金流量表/api/report/export/cash-flow.xlsx

7.3 風險預警（risk）

展示 Z-Score / Z2 / Z3 三模型分數及流動比率、負債比、ROE / ROA、毛利率、淨利率等指標。可執行 POST /api/risk/calc 計算當月風險等級，結果寫入 MGM_finance_summary 的 risk_color、wall_mode 等欄位。

需先跑過風險計算的月份才有 Z 值；未計算的月份 Z=0，儀表板彈窗變數值會顯示「-」。

7.4 財務預測（forecast）

按月錄入預測數據（銷售額、成本、費用等），bu_no + YYYY_MM + forecast_type 為唯一鍵，支援 UPSERT。

7.5 年度趨勢（trend）

Chart.js 折線圖展示全年 12 個月的收入/成本/利潤趨勢，支援多公司比較。

7.6 月結項目（monthly）

月結調整分錄管理，記錄每月結帳的調整項目。

7.7 損益平衡分析 BEP（bep）

基於 CW397 基準的損益平衡分析頁面，包含：

  • 材料成本 7 項：點擊各材料項目卡片 → 彈出明細視窗（來源：現金日記帳對應科目）
  • 變動費用：差旅費 / 廣告費 / 設備維修 三項明細
  • 固定成本 NEW：點擊卡片 → 彈出可編輯視窗（工資 / 廠租水電 / 利息支出），修改金額後 250ms 防抖即時重算 BEP
  • 門檻值儲存：修改後點「儲存門檻」→ POST /api/bep/save 寫入 mgm_bep_threshold
  • 勾稽核驗：node database/check_bep_reconcile_all.js 驗證明細合計 = 門檻值

7.8 會計科目（account）

會計科目主檔管理，樹狀結構顯示資產/負債/權益/收入/費用等類別下的科目代碼與名稱。

7.9 庫存減值（xitems）

庫存日狀態與跌價減值管理，由批次管線 Step5 加工產出。頁面展示庫存明細與帳齡分析。

8. KPI 預警查詢（YG001–YG004）

四個 KPI 模型頁面，各有不同分析視角：

📊

YG001 預警指標

財務健康度預警，點擊預警類別卡片可展開彈窗查看該類別下所有指標的目的、公式、判讀方式

📈

YG002 指標管理

指標定義與門檻值管理，支援編輯目標值

⚠️

YG003 報表異常甄別

自動偵測報表數據異常（如資產負債不平衡、利潤率驟變等）

🎯

YG004 預測模型分析

三種模型卡片：營運資產模型（藍）、沃爾比重模型（橙）、A 值模型（紅），支援目標值編輯

YG001–YG004 的指標定義存於 MGM_KPI_desc 表，公式計算由 routes/kpiQuery.js 執行。點擊類別卡片彈窗顯示該類別下所有指標的說明。

9. 主檔管理

9.1 KPI 門檻（kpi）

管理 KPI 指標定義與門檻值，記錄指標代碼、名稱、公式、目標值、上下限。YG004 模型需確保 MGM_KPI_desc 表有對應 uid 記錄才能編輯目標值。

9.2 分公司（branch）

公司/分行主檔，維護 bu_no（HM / HN / SZ）、公司名稱、地址等。跨表 bu_no 必須與此處一致。

9.3 往來對象（relation）

客戶/供應商/關係人主檔，記錄往來代碼、名稱、類型、統一編號等。

10. 系統管理

10.1 批次管線（batch）

七步財務加工管線的核心入口：

步驟名稱產出表說明
Step1erp2ermm_poermm_erp_po暫存 PO → 正式 PO
Step2proc_po—PO 本幣金額加工（×匯率）
Step3proc_supplier—供應商彙算
Step4proc_xitems—物料法規綁定（可跳過）
Step5cal_daily_stocke2_xitems_daily_status_chart庫存日結算、跌價
Step6batch_ARAP_updERMM_arap_detailAR/AP 彙算
Step7finance_summaryMGM_finance_summary三大報表重算

頁面提供「一鍵執行全部」按鈕（POST /api/batch/runAll），也可單步執行。每步執行狀態記錄於 cams_batch_control 表。

每月例行必做：資料匯入後必須跑 runAll，三大報表數字才會更新。

10.2 系統設定（system）

管理系統碼表（cams_system_codes），包含庫存帳齒分類、狀態選項等。碼表 value_description 為中文值，前端以 t() 或 I18N.statusLabel() 翻譯顯示，但 DB 存儲和後端查詢依賴中文原值，不可改為英文。

10.3 使用者管理（user）

系統使用者帳號管理，記錄帳號、密碼、權限。支援 PUT /:user_id/permissions 修改權限。登入記錄寫入 login_user_record。

11. 多語言切換（i18n）

系統支援三種語言即時切換，覆蓋全部 27 頁面的 UI 元素（按鈕、表頭、標題、彈窗、導航、狀態標籤等）。

操作方式

  1. 點擊頂部導航列的「語言」下拉選擇器
  2. 選擇目標語言（繁體中文 / 简体中文 / English）
  3. 頁面即時刷新，所有 UI 文案切換為所選語言
  4. 切回原語言同樣即時生效，無需重新載入頁面
設計原則：業務數據（如 KPI 公式、報表項目）保持原文不翻譯；狀態選項（如「未審核」「審核通過」）DB 存中文值，前端以 t() 翻譯顯示標籤但保留原始值供後端查詢。

新增翻譯 key

若新增頁面文案，需在 public/js/i18n.js 的三個語言物件中同步加入同名 key，否則 t() 會回退顯示 key 名稱。

12. Excel 匯出

三大報表頁面支援一鍵匯出 .xlsx 檔案，使用 ExcelJS 生成：

報表匯出按鈕位置路由
資產負債表三大報表頁 → 資產負債表頁籤 → 匯出/api/report/export/balance-sheet.xlsx
損益表三大報表頁 → 損益表頁籤 → 匯出/api/report/export/pl-table.xlsx
現金流量表三大報表頁 → 現金流量表頁籤 → 匯出/api/report/export/cash-flow.xlsx

匯出檔案會以當前選中的公司別 + 月份為篩選條件，包含格式化的表頭、數據行和合計行。

13.3 開發者提示

  • 前端改完按 Ctrl+F5 即可，不需重啟服務（Express 靜態檔設 no-cache）
  • 後端 routes 改完需重啟 node app.js
  • PowerShell 中文 JSON body 需用 [System.Text.Encoding]::UTF8.GetBytes()
  • 全域函數名在各頁面 JS 中必須唯一（避免 system.js 和 kpi.js 的 loadKPI 衝突教訓）
  • HTML 內聯 onclick 傳參需把 " 轉為 " 避免雙引號截斷
