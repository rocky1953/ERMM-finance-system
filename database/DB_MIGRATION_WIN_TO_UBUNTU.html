一、遷移概覽與環境資訊

來源：Windows Server 2019

  • MySQL 8.0（MySQL80 服務）
  • 資料庫名：ermm_db
  • 字符集：utf8mb4
  • 應用帳號：ermm_app
  • 備份帳號：ermm_backup
  • 密碼：aaabbb123
  • my.ini 路徑：C:\ProgramData\MySQL\MySQL Server 8.0\my.ini
  • mysqldump 路徑：C:\Program Files\MySQL\MySQL Server 8.0\bin\

目標：Ubuntu 22.04 / 24.04 LTS

  • MySQL 8.0（mysql.service）
  • 資料庫名：ermm_db（保持一致）
  • 字符集：utf8mb4（保持一致）
  • 應用帳號：ermm_app（重建）
  • 備份帳號：ermm_backup（重建）
  • 密碼：aaabbb123（保持一致）
  • 設定檔路徑：/etc/mysql/mysql.conf.d/mysqld.cnf
  • mysqldump 路徑：/usr/bin/mysqldump

二、階段 0：前置準備

0-1. 確認兩端 MySQL 版本相容

Windows 端（PowerShell）

# 確認 MySQL 版本
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e "SELECT VERSION();"

# 確認資料庫存在
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e "SHOW DATABASES LIKE 'ermm_db';"

# 確認表數量
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p ermm_db -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='ermm_db';"

Ubuntu 端（SSH）

# 確認 MySQL 已安裝且運行
sudo systemctl status mysql
mysql --version

# 確認 MySQL 已初始化（空資料庫尚未建）
sudo mysql -e "SHOW DATABASES;"

0-2. 確認字符集一致

# Windows 端
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p ermm_db -e "SHOW VARIABLES LIKE 'character%';"

# 預期輸出：
# character_set_database | utf8mb4
# character_set_server   | utf8mb4
# collation_database    | utf8mb4_unicode_ci
# collation_server       | utf8mb4_unicode_ci

0-3. 停止應用服務（避免遷移期間寫入新資料）

Windows 端

# 停止 ERMM-Finance 服務
Stop-Service ERMM-Finance

# 確認已停止
Get-Service ERMM-Finance

Ubuntu 端（如已有舊服務）

# 停止應用服務
sudo systemctl stop ermm-finance

# 確認已停止
sudo systemctl status ermm-finance

0-4. 記錄遷移前基準值（用於匯入後對比）

# Windows 端：記錄各表記錄數（存到檔案方便對比）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p ermm_db -e "
SELECT table_name, table_rows
FROM information_schema.tables
WHERE table_schema='ermm_db'
ORDER BY table_name;
" | Out-File -FilePath C:\temp\table_counts_before.txt -Encoding utf8

Get-Content C:\temp\table_counts_before.txt
建議在離峰時段執行遷移：停止應用服務後到匯入完成期間，系統無法使用。22 張表通常在 1~5 分鐘內完成匯出匯入。

三、階段 1：Windows 端匯出

1-1. 完整匯出（表結構 + 資料 + 觸發器 + 預存程序）

# 在 Windows Server 上以管理員 PowerShell 執行

# 設定 mysqldump 路徑變數
$mysqldump = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe"

# 完整匯出（一筆交易一致性 + 觸發器 + 預存程序 + utf8mb4）
& $mysqldump -u root -p \
  --default-character-set=utf8mb4 \
  --single-transaction \
  --routines \
  --triggers \
  --events \
  --set-gtid-purged=OFF \
  --column-statistics=0 \
  ermm_db > C:\temp\ermm_db_migration.sql

# 另外匯出表結構（備用，用於對比）
& $mysqldump -u root -p \
  --default-character-set=utf8mb4 \
  --no-data \
  --routines \
  --triggers \
  ermm_db > C:\temp\ermm_db_schema.sql
參數說明：
  • --single-transaction：InnoDB 一致性快照匯出，不鎖表
  • --routines：包含預存程序（PROCEDURE）和函數（FUNCTION）
  • --triggers：包含觸發器
  • --events：包含事件排程器（EVENT）
  • --set-gtid-purged=OFF：避免 GTID 衝突（跨伺服器遷移必加）
  • --column-statistics=0：MySQL 8 的 mysqldump 預設會查 column_statistics，舊版 MySQL 或某些設定下會報錯，加此參數跳過

1-2. 驗證匯出檔案

# 檢查檔案大小（不應為 0）
Get-Item C:\temp\ermm_db_migration.sql | Select-Object Name, @{N='SizeMB';E={[math]::Round($_.Length/1MB,2)}}

# 檢查檔案頭部（應有 -- MySQL dump ...）
Get-Content C:\temp\ermm_db_migration.sql -TotalCount 5

# 檢查檔案尾部（應有 -- Dump completed）
Get-Content C:\temp\ermm_db_migration.sql -Tail 5

# 統計 CREATE TABLE 數量（應約 22）
(Select-String -Path C:\temp\ermm_db_migration.sql -Pattern "^CREATE TABLE" | Measure-Object).Count

# 統計 INSERT 語句數量
(Select-String -Path C:\temp\ermm_db_migration.sql -Pattern "^INSERT INTO" | Measure-Object).Count

1-3. 匯出帳號權限定義（參考用）

# 查看現有帳號與權限（用於在 Ubuntu 端重建）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e "
SELECT user, host, authentication_string != '' AS has_password FROM mysql.user WHERE user IN ('ermm_app','ermm_backup');
SHOW GRANTS FOR 'ermm_app'@'localhost';
SHOW GRANTS FOR 'ermm_backup'@'localhost';
" | Out-File C:\temp\account_grants.txt -Encoding utf8

Get-Content C:\temp\account_grants.txt

四、階段 2：傳輸到 Ubuntu

方式 A：SCP 傳輸（推薦，需 SSH 連通）

# 在 Windows PowerShell 執行（需有 OpenSSH Client）
# 安裝：Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0

# 上傳匯出檔到 Ubuntu
scp C:\temp\ermm_db_migration.sql root@Ubuntu伺服器IP:/tmp/

# 上傳基準對比檔
scp C:\temp\table_counts_before.txt root@Ubuntu伺服器IP:/tmp/

# 上傳帳號權限參考
scp C:\temp\account_grants.txt root@Ubuntu伺服器IP:/tmp/

方式 B：壓縮後傳輸（大檔案推薦）

# Windows 端壓縮
Compress-Archive -Path C:\temp\ermm_db_migration.sql -DestinationPath C:\temp\ermm_db_migration.zip

# 上傳壓縮檔
scp C:\temp\ermm_db_migration.zip root@Ubuntu伺服器IP:/tmp/

# Ubuntu 端解壓
ssh root@Ubuntu伺服器IP
cd /tmp
unzip ermm_db_migration.zip
ls -lh ermm_db_migration.sql

方式 C：USB / 網路共用（無 SSH 時）

# 將 C:\temp\ermm_db_migration.sql 拷貝到 USB 隨身碟
Copy-Item C:\temp\ermm_db_migration.sql E:\

# 或透過網路共用資料夾傳輸
# 在 Ubuntu 端掛載 SMB 共用：
# sudo mount -t cifs //WindowsIP/共用名 /mnt -o username=user,password=pass
# cp /mnt/ermm_db_migration.sql /tmp/

Ubuntu 端確認檔案已到達

# 在 Ubuntu 上確認
ls -lh /tmp/ermm_db_migration.sql

# 檢查頭尾
head -5 /tmp/ermm_db_migration.sql
tail -5 /tmp/ermm_db_migration.sql

# 統計 CREATE TABLE 數量
grep -c "^CREATE TABLE" /tmp/ermm_db_migration.sql

五、階段 3：Ubuntu 端匯入

3-1. 確認 MySQL 已安裝且運行

sudo systemctl status mysql
mysql --version
# 預期：mysql  Ver 8.0.x

3-2. 建立空資料庫

sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS ermm_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
SQL

# 確認
sudo mysql -e "SHOW CREATE DATABASE ermm_db;"

3-3. 匯入 SQL 檔案

# 方式 A：用 root 匯入（最穩定，無權限問題）
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql

# 方式 B：用 ermm_app 匯入（需先建好帳號，見階段 4）
mysql -u ermm_app -p --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql
大檔案匯入加速：如果 SQL 檔超過 100MB，匯入前可先關閉外鍵檢查和唯一性檢查，匯入後再開啟： 
sudo mysql ermm_db -e "SET GLOBAL foreign_key_checks=0; SET GLOBAL unique_checks=0;"
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql
sudo mysql ermm_db -e "SET GLOBAL foreign_key_checks=1; SET GLOBAL unique_checks=1;"

3-4. 匯入後立即確認

# 確認表數量
sudo mysql ermm_db -e "SELECT COUNT(*) AS table_count FROM information_schema.tables WHERE table_schema='ermm_db';"
# 預期：約 22

# 確認表清單
sudo mysql ermm_db -e "SHOW TABLES;"

# 對比記錄數（與 Windows 端的 table_counts_before.txt 比對）
sudo mysql ermm_db -e "
SELECT table_name, table_rows
FROM information_schema.tables
WHERE table_schema='ermm_db'
ORDER BY table_name;
" > /tmp/table_counts_after.txt

# 對比
diff /tmp/table_counts_before.txt /tmp/table_counts_after.txt
# 若無輸出 = 完全一致

六、階段 4：帳號與權限遷移

mysqldump 不會匯出 MySQL 使用者帳號，需要在 Ubuntu 端手動建立。

4-1. 建立應用帳號 ermm_app

sudo mysql <<'SQL'
CREATE USER IF NOT EXISTS 'ermm_app'@'localhost'
  IDENTIFIED BY 'aaabbb123';
GRANT ALL PRIVILEGES ON ermm_db.* TO 'ermm_app'@'localhost';
FLUSH PRIVILEGES;
SQL

# 驗證帳號可登入且能存取資料
mysql -u ermm_app -p ermm_db -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='ermm_db';"

4-2. 建立備份帳號 ermm_backup

sudo mysql <<'SQL'
CREATE USER IF NOT EXISTS 'ermm_backup'@'localhost'
  IDENTIFIED BY 'aaabbb123';
GRANT SELECT, SHOW VIEW, TRIGGER, LOCK TABLES
  ON ermm_db.* TO 'ermm_backup'@'localhost';
FLUSH PRIVILEGES;
SQL

# 驗證備份帳號可執行 mysqldump
mysqldump -u ermm_backup -p --single-transaction ermm_db > /dev/null
# 無錯誤即成功

4-3. 建立備份帳號認證檔

sudo nano /etc/mysql/backup.cnf
[mysqldump]
user=ermm_backup
password=aaabbb123
host=127.0.0.1
sudo chmod 600 /etc/mysql/backup.cnf

# 驗證
sudo mysqldump --defaults-file=/etc/mysql/backup.cnf --single-transaction ermm_db > /dev/null
echo "Backup account OK: $?"

十、回滾方案

回滾條件：匯入後發現資料不完整、字符集錯誤、或 API 異常，且無法快速修復時。

方案 A：Ubuntu 端重新匯入（最常見）

# 1. 刪除有問題的資料庫
sudo mysql -e "DROP DATABASE IF EXISTS ermm_db;"

# 2. 重建空資料庫
sudo mysql -e "CREATE DATABASE ermm_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. 重新匯入
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql

# 4. 重建帳號（帳號不隨 DB 刪除而消失，但若需重建）
sudo mysql -e "DROP USER IF EXISTS 'ermm_app'@'localhost';"
sudo mysql <<'SQL'
CREATE USER 'ermm_app'@'localhost' IDENTIFIED BY 'aaabbb123';
GRANT ALL PRIVILEGES ON ermm_db.* TO 'ermm_app'@'localhost';
FLUSH PRIVILEGES;
SQL

方案 B：退回 Windows 端（應用回退）

# Windows 端重新啟動服務
Start-Service ERMM-Finance

# 確認 API 正常
Invoke-RestMethod http://localhost:3008/api/health

# 更新 DNS / Nginx 指回 Windows Server

方案 C：使用結構備份重建

# 如果完整匯入失敗，可先用結構檔建表，再逐表匯入
sudo mysql ermm_db < /tmp/ermm_db_schema.sql
# 然後逐表單獨匯出匯入

十一、常見問題

問題 1：匯入時報 "Unknown collation 'utf8mb4_0900_ai_ci'"

# 原因：Windows MySQL 8.0 預設排序規則與 Ubuntu MySQL 版本不同
# 解法：匯入前在 SQL 檔中替換排序規則
sed -i 's/utf8mb4_0900_ai_ci/utf8mb4_unicode_ci/g' /tmp/ermm_db_migration.sql
sed -i 's/utf8mb4_0900_as_cs/utf8mb4_unicode_ci/g' /tmp/ermm_db_migration.sql
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql

問題 2：匯入時報 "Access denied for user 'ermm_app'"

# 原因：帳號尚未建立或權限不足
# 解法：先用 root 匯入，再建帳號
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql

# 然後建立帳號（見階段 4）

問題 3：匯入時報 "Row size too large"

# 原因：MySQL 的 InnoDB 行格式限制
# 解法：匯入前臨時調整
sudo mysql -e "SET GLOBAL innodb_strict_mode=0;"
sudo mysql --default-character-set=utf8mb4 ermm_db < /tmp/ermm_db_migration.sql
sudo mysql -e "SET GLOBAL innodb_strict_mode=1;"

問題 4：中文資料亂碼

# 原因：匯出或匯入時未指定 utf8mb4
# 確認：匯出和匯入都必須帶 --default-character-set=utf8mb4

# 檢查當前字符集
sudo mysql ermm_db -e "SHOW VARIABLES LIKE 'character%';"

# 如果資料庫字符集不對，需修正：
sudo mysql -e "ALTER DATABASE ermm_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 如果表字符集不對，逐表修正：
sudo mysql ermm_db -e "
SELECT CONCAT('ALTER TABLE \`', table_name, '\` CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;')
FROM information_schema.tables
WHERE table_schema='ermm_db' AND table_collation NOT LIKE 'utf8mb4%';
" | sudo mysql ermm_db
