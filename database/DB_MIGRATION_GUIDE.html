核心原則：整個遷移使用 MySQL 原生 mysqldump 工具，確保表結構、資料、索引、觸發器、存儲過程全部完整保留。無需第三方軟體。

項目要求確認方法
源伺服器 MySQL8.0+ 已安裝 mysqldumpmysqldump --version
目標伺服器 MySQL8.0+ 已安裝mysql --version
Node.js18+ 已安裝於目標伺服器node --version

磁碟空間至少 2GB 可用Get-PSDrive
端口可用3008（應用）、3306（DB）netstat -ano | findstr :3008
版本一致性：源和目標 MySQL 最好同為 8.0+，避免 utf8mb4 排序規則差異。如果源是 8.0、目標是 5.7，需在導入時加 --force 並可能遺失 8.0 特有功能。

三、階段一：源伺服器導出

方法 A：完整 SQL 導出（推薦）

在源伺服器以 PowerShell 執行，產出單一 .sql 備份檔，包含表結構 + 資料 + 觸發器 + 存儲過程。

# 1. 完整導出（表結構 + 資料 + 觸發器 + 存儲過程）
mysqldump -u root -p --default-character-set=utf8mb4 --routines --triggers --single-transaction ERMM_db > E:\ERMM_db_full.sql

# 2. 單獨導出表結構（備用，用於對比）
mysqldump -u root -p --default-character-set=utf8mb4 --no-data ERMM_db > E:\ERMM_db_schema.sql

# 3. 單獨導出資料（不含表結構，備用）
mysqldump -u root -p --default-character-set=utf8mb4 --no-create-info --single-transaction ERMM_db > E:\ERMM_db_data.sql
參數說明：
  • --single-transaction：InnoDB 無鎖導出，不影響線上服務
  • --routines：包含存儲過程和函數
  • --triggers：包含觸發器
  • --default-character-set=utf8mb4：確保中文資料正確

方法 B：Excel 導出（僅用於人工審查）

專案內已有 22 張表的 Excel 導出工具，產出 .xlsx 供人工核對，但不適合完整遷移（遺失表結構、索引、約束）。

# 在源伺服器執行
cd e:\finance
node database\export_tables_to_excel.js
# 輸出至 database/exports/ 目錄

確認導出檔大小

# 確認備份檔大小
Get-Item E:\ERMM_db_full.sql | Select-Object Name, @{N='Size(MB)';E={[math]::Round($_.Length/1MB,1)}}
# 預期輸出：ERMM_db_full.sql  Size(MB): 5~50

四、階段二：傳輸至目標伺服器

方式 1：USB / 網路直接拷貝

# 將 SQL 備份檔拷貝至目標伺服器
Copy-Item E:\ERMM_db_full.sql \\目標伺服器\共享目錄\

# 或 USB 拷貝

方式 2：壓縮後傳輸（大檔案推薦）

# 源伺服器壓縮
Compress-Archive -Path E:\ERMM_db_full.sql -DestinationPath E:\ERMM_db_full.zip
# 壓縮比通常 60~80%

# 目標伺服器解壓
Expand-Archive -Path C:\temp\ERMM_db_full.zip -DestinationPath C:\temp\

方式 3：SCP / 遠端傳輸（跨網段）

# 使用 scp（如果目標伺服器有 SSH）
scp E:\ERMM_db_full.sql user@目標IP:C:\temp\

# 或使用 PowerShell 遠端複製
Copy-Item E:\ERMM_db_full.sql -Destination \\目標IP\c$\temp\ -Credential (Get-Credential)

五、階段三：目標伺服器導入

步驟 1：安裝 MySQL 8.0（如未安裝）

下載地址：https://dev.mysql.com/downloads/installer/

安裝要點：選擇 Server Only；設定 root 密碼；字符集選 utf8mb4；端口 3306。 安裝後確認服務已啟動：Get-Service mysql*

步驟 2：建立空資料庫

# 在目標伺服器 PowerShell 執行
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS ERMM_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 確認建立成功
mysql -u root -p -e "SHOW DATABASES LIKE 'ERMM%';"

步驟 3：導入 SQL 備份檔

# 導入完整資料庫（表結構 + 資料 + 觸發器 + 存儲過程）
mysql -u root -p --default-character-set=utf8mb4 ERMM_db < C:\temp\ERMM_db_full.sql

# 如果檔案很大，加 --force 跳過非致命錯誤繼續導入
mysql -u root -p --default-character-set=utf8mb4 --force ERMM_db < C:\temp\ERMM_db_full.sql
注意：導入過程可能需要數分鐘到數十分鐘，取決於資料量。期間不要中斷。

步驟 4：建立應用專用帳號（推薦，不用 root 連線）

# 在 mysql 命令行執行
CREATE USER 'ermm_app'@'localhost' IDENTIFIED BY '你的強密碼';
CREATE USER 'ermm_app'@'%' IDENTIFIED BY '你的強密碼';

GRANT ALL PRIVILEGES ON ERMM_db.* TO 'ermm_app'@'localhost';
GRANT ALL PRIVILEGES ON ERMM_db.* TO 'ermm_app'@'%';
FLUSH PRIVILEGES;

步驟 5：確認表數量

# 確認所有表已建立
mysql -u root -p ERMM_db -e "SHOW TABLES;"
# 預期輸出：~22 張表

六、階段四：部署應用 + 驗證

步驟 4：資料完整性驗證

4-1. API 健康檢查

# 驗證 API 服務正常
Invoke-RestMethod -Uri "http://localhost:3008/api/health" | ConvertTo-Json

4-2. 各表記錄數統計

# 驗證各表資料筆數
node -e "
const {pool} = require('./config/db');
(async()=>{
  const tables = [
    'MGM_finance_summary','forecast_detail','MGM_KPI_desc',
    'MGM_BEP_threshold','MGM_BEP_detail','MGM_cash_journal',
    'MGM_account_details','ermm_erp_so_dn','ermm_erp_po',
    'ermm_erp_arap','cams_xuser','cams_branch'
  ];
  for(const t of tables){
    const [r] = await pool.execute('SELECT COUNT(*) c FROM '+t);
    console.log(t.padEnd(30), r[0].c, '筆');
  }
  process.exit(0);
})()
"

4-3. 資產負債表平衡驗證

# 驗證資產 = 負債 + 權益
node -e "
const {pool} = require('./config/db');
(async()=>{
  const [rows] = await pool.execute(
    'SELECT COUNT(*) as total, ' +
    'SUM(CASE WHEN ABS(ttl_asset_amt - ttl_debet_amt - stockholder_amt) < 1 THEN 1 ELSE 0 END) as balanced ' +
    'FROM MGM_finance_summary'
  );
  console.log('資產負債平衡:', rows[0].balanced, '/', rows[0].total);
  process.exit(0);
})()
"

4-4. 預測資料驗證

# 驗證預測 vs 實際對比 API 回傳非零值
Invoke-RestMethod -Uri "http://localhost:3008/api/forecast/compare?bu_no=HM&year=2025&forecast_type=Sales" | ConvertTo-Json -Depth 3

八、常見問題排查

問題 1：導入時出現 "Unknown collation 'utf8mb4_0900_ai_ci'"

原因：源伺服器 MySQL 8.0 導出的排序規則在目標 5.7 不支援。 
# 解法：在導入前替換排序規則
(Get-Content C:\temp\ERMM_db_full.sql) |
  ForEach-Object { $_ -replace 'utf8mb4_0900_ai_ci','utf8mb4_unicode_ci' } |
  Set-Content C:\temp\ERMM_db_fixed.sql
mysql -u root -p ERMM_db < C:\temp\ERMM_db_fixed.sql

問題 2：中文亂碼

原因：導出或導入時未指定 utf8mb4 字符集。 
# 確保導出和導入都加 --default-character-set=utf8mb4
mysqldump -u root -p --default-character-set=utf8mb4 ERMM_db > backup.sql
mysql -u root -p --default-character-set=utf8mb4 ERMM_db < backup.sql

問題 3：端口 3008 已被佔用

# 找到佔用 3008 端口的進程
netstat -ano | findstr :3008
# 輸出最後一欄是 PID，例如 12345

# 停止該進程
Stop-Process -Id 12345 -Force

# 重新啟動
node app.js

問題 4：應用連不上資料庫

症狀：啟動時顯示 ❌ 資料庫連線失敗 
# 1. 確認 MySQL 服務運行
Get-Service mysql*

# 2. 確認 .env 設定正確
Get-Content .env | Select-String "DB_"

# 3. 手動測試連線
mysql -u ermm_app -p -e "SELECT 1;"

# 4. 確認防火牆未擋 3306
netsh advfirewall firewall add rule name="MySQL" dir=in action=allow protocol=TCP localport=3306

問題 5：Git clone 失敗（網路問題）

# 方式 A：重試
git clone https://github.com/rocky1953/ERMM-finance-system.git

# 方式 B：直接拷貝（不走 Git）
# 將 e:\finance 整個目錄壓縮拷貝到目標伺服器解壓

問題 6：PowerShell 執行 node 腳本被擋

原因：PowerShell 預設禁止執行未簽署腳本。 
# 使用 .cmd 版本或直接用 node 執行 .js 檔（不走 .ps1）
node app.js              # 直接執行，不受執行策略影響
npm.cmd install          # 用 .cmd 版本

九、回滾方案

回滾時機：遷移後發現資料異常或應用無法正常運作，需還原至源伺服器。

情況 A：目標伺服器有問題，源伺服器未動

# 源伺服器未停止過服務 → 直接在源伺服器繼續使用即可
# 無需回滾操作

情況 B：源伺服器已被修改

# 1. 用遷移前的備份檔還原源伺服器
mysql -u root -p --default-character-set=utf8mb4 ERMM_db < E:\ERMM_db_full.sql

# 2. 重啟應用
node app.js

情況 C：需要保留目標伺服器的新資料

# 1. 從目標伺服器反向導出
mysqldump -u ermm_app -p --single-transaction --default-character-set=utf8mb4 ERMM_db > C:\ERMM_db_new.sql

# 2. 傳輸回源伺服器

# 3. 在源伺服器導入
mysql -u root -p --default-character-set=utf8mb4 ERMM_db < E:\ERMM_db_new.sql
最佳實踐：遷移前確保源伺服器服務不停止，先在目標伺服器完整驗證通過後，再切換流量。這樣回滾只需把流量指回源伺服器即可，零風險。
