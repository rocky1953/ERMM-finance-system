Part A：GitHub 更新操作（Windows → GitHub → Ubuntu）

A-1. Windows 本機提交並推送到 GitHub

在 Windows 開發環境（e:\finance）中，將修改後的程式碼提交並推送到 GitHub：

# 1. 進入專案目錄
cd e:\finance

# 2. 查看修改的檔案
git status

# 3. 暫存所有修改的檔案（排除敏感資料）
git add app.js package.json package-lock.json \
  public/css/style.css public/index.html \
  public/js/app.js public/js/i18n.js \
  public/js/pages/*.js \
  routes/*.js middleware/*.js \
  database/*.js database/*.html

# 4. 提交（撰寫有意義的 commit message）
git commit -m "feat(auth,user): login authentication + admin role + user profile fields"

# 5. 推送到 GitHub
git push origin main
注意：不要提交 .env、ERMM_db_full.sql 等含敏感資料的檔案。.gitignore 應已排除這些檔案，但每次提交前仍需確認 git status 未列出它們。
驗證：推送成功後，到 GitHub 頁面 https://github.com/rocky1953/ERMM-finance-system 確認最新 commit 出現在 main 分支頂部。

A-2. Ubuntu 從 GitHub 拉取最新程式碼

SSH 登入 Ubuntu 伺服器後，執行以下操作：

# 1. 進入部署目錄
cd /root/Project/ERMM-finance-system

# 2. 確認目前分支與遠端狀態
git branch -vv
git remote -v

# 3. 拉取最新程式碼
git pull origin main

# 4. 確認更新後的檔案清單
git log --oneline -5
首次部署（全新機器）：如果伺服器上還沒有專案目錄，需先克隆： 
git clone https://github.com/rocky1953/ERMM-finance-system.git /root/Project/ERMM-finance-system
如果 git pull 出現衝突：表示伺服器上有本地修改（如 .env 被手動改過），先暫存： 
git stash
git pull origin main
git stash pop  # 恢復本地修改，如有衝突需手動解決

A-3. 安裝/更新 npm 依賴

如果 package.json 有變動（新增了 jsonwebtoken、bcryptjs 等依賴），必須重新安裝：

# 1. 進入專案目錄
cd /root/Project/ERMM-finance-system

# 2. 安裝依賴（生產環境用 --production，不含 devDependencies）
npm install --production

# 3. 確認新增的依賴已安裝
node -e "require('jsonwebtoken'); require('bcryptjs'); console.log('✅ auth deps OK')"
驗證：執行 npm ls jsonwebtoken bcryptjs 確認兩個套件已安裝。

Part B：系統配置更新（MySQL + Node.js + 環境變數）

B-1. MySQL 資料庫配置

確認 MySQL 服務運行

# 檢查 MySQL 服務狀態
systemctl status mysql

# 如果未運行，啟動 MySQL
systemctl start mysql

# 設定開機自動啟動
systemctl enable mysql

登入 MySQL 並確認資料庫

建立專用資料庫使用者（ermm_user）

基於安全考量，不使用 root 帳號連線應用程式，而是建立專用使用者 ermm_user：

# 以 root 登入 MySQL
mysql -u root -p

# 在 MySQL 提示字元下執行：

# 建立專用使用者並設定密碼
CREATE USER 'ermm_user'@'localhost' IDENTIFIED BY 'LD*6835755';

# 授予 ermm_db 資料庫完整權限
GRANT ALL PRIVILEGES ON ermm_db.* TO 'ermm_user'@'localhost';

# 立即生效
FLUSH PRIVILEGES;

# 驗證使用者已建立
SELECT user, host FROM mysql.user WHERE user='ermm_user';

# 確認資料庫
SHOW DATABASES;
USE ermm_db;
SHOW TABLES;
SELECT COUNT(*) FROM cams_xuser;
驗證 ermm_user 連線：退出 root 後，用 ermm_user 登入測試： 
mysql -u ermm_user -p ermm_db
# 輸入密碼：LD*6835755
# 應成功進入 mysql> 提示字元
正式環境參數：
項目值
資料庫名稱ermm_db
應用程式使用者ermm_user
應用程式密碼LD*6835755
字集utf8mb4 / utf8mb4_unicode_ci

B-2. 新增登入認證欄位（cams_xuser 表遷移）

重要：本次更新新增了登入認證功能，需要在 cams_xuser 表增加 admin、email、tel_no、xuser_type 四個欄位。執行以下遷移腳本即可自動完成。

執行欄位遷移腳本

# 1. 進入專案目錄
cd /root/Project/ERMM-finance-system

# 2. 確保環境變數已載入（USE_DB_CONFIG=true 才會使用正式環境資料庫）
export USE_DB_CONFIG=true

# 3. 執行 admin 欄位遷移
node database/add_admin_column.js

# 4. 執行 email/tel_no/xuser_type 欄位遷移
node database/add_user_cols.js
預期輸出： 
✅ 已新增欄位: admin
✅ 已新增欄位: email
✅ 已新增欄位: tel_no
✅ 已新增欄位: xuser_type
目前分布: 管理員=1, 普通者=29
目前分布: 一般員工=30

驗證欄位結構

# 用 MySQL 命令列確認欄位已加入
mysql -u ermm_user -p ermm_db -e "DESCRIBE cams_xuser"

# 確認 U0001 為管理員
mysql -u ermm_user -p ermm_db -e "SELECT xuser_id, xuser_name, admin, xuser_type FROM cams_xuser WHERE xuser_id='U0001'"

設定管理員帳號（如需調整）

# 將指定帳號設為管理員
mysql -u ermm_user -p ermm_db -e "UPDATE cams_xuser SET admin='管理員' WHERE xuser_id='U0001'"

# 設定使用者類別
mysql -u ermm_user -p ermm_db -e "UPDATE cams_xuser SET xuser_type='部門經理' WHERE xuser_id='U0002'"
欄位類型合法值預設值
adminVARCHAR(10)管理員 / 普通者普通者
emailVARCHAR(100)—NULL
tel_noVARCHAR(30)—NULL
xuser_typeVARCHAR(20)一般員工 / 部門經理 / 高階主管一般員工

B-4. PM2 服務管理與啟動

首次安裝 PM2

npm install -g pm2

啟動/重啟服務

# 進入專案目錄
cd /root/Project/ERMM-finance-system

# 首次啟動（指定 app.js 並命名為 ermm-finance）
pm2 start app.js --name ermm-finance

# 更新程式碼後重啟
pm2 restart ermm-finance

# 設定開機自動啟動
pm2 save
pm2 startup

PM2 服務管理指令

操作指令說明
查看狀態pm2 status列出所有 PM2 管理的服務
查看日誌pm2 logs ermm-finance --lines 50即時查看最近 50 行日誌
停止服務pm2 stop ermm-finance停止服務但不從 PM2 移除
重新啟動pm2 restart ermm-finance重啟服務（更新程式碼後執行）
刪除服務pm2 delete ermm-finance從 PM2 列表中移除
監控面板pm2 monit即時 CPU/記憶體監控
服務 systemd 單元檔（替代方案）：如果不用 PM2，也可建立 systemd 服務： 
# /etc/systemd/system/ermm-finance.service
[Unit]
Description=ERMM Finance Module
After=network.target mysql.service redis-server.service

[Service]
Type=simple
User=root
WorkingDirectory=/root/Project/ERMM-finance-system
EnvironmentFile=/root/Project/ERMM-finance-system/.env
ExecStart=/usr/bin/node /root/Project/ERMM-finance-system/app.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
啟用方式：systemctl daemon-reload && systemctl enable ermm-finance && systemctl start ermm-finance

B-5. Nginx 反向代理確認

確認 Nginx 將外部請求轉發到 Node.js 服務（端口 3008）：

# 檢查 Nginx 服務狀態
systemctl status nginx

# 確認設定檔中的 proxy_pass 指向 3008
cat /etc/nginx/sites-available/default | grep proxy_pass

# 應看到類似：
# proxy_pass http://localhost:3008;

# 如有修改，測試設定檔語法
nginx -t

# 重新載入 Nginx
systemctl reload nginx
Nginx 不需額外配置：所有路由分發邏輯都在 Node.js app.js 中處理，Nginx 僅作為反向代理轉發到 localhost:3008。新增功能只需更新 Node.js 路由檔案，無需修改 Nginx 配置。

Part C：驗證步驟

C-1. 服務健康檢查

# 1. 確認服務進程在運行
pm2 status

# 2. 確認端口 3008 正在監聽
ss -tlnp | grep 3008

# 3. 健康檢查 API（不需登入）
curl http://localhost:3008/api/health
預期回應： 
{
  "success": true,
  "service": "ERMM Finance Module",
  "version": "1.0.0",
  "timestamp": "2026-09-21T...",
  ...
}

C-2. 登入功能驗證

# 1. 測試正確帳號登入（U0001 / 68315711）
curl -X POST http://localhost:3008/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"user_id":"U0001","password":"68315711"}'

# 2. 測試錯誤密碼（應回傳 401）
curl -X POST http://localhost:3008/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"user_id":"U0001","password":"wrongpwd"}'

# 3. 測試不存在的帳號（應回傳 401）
curl -X POST http://localhost:3008/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"user_id":"NOEXIST","password":"123456"}'
正確登入的預期回應： 
{
  "success": true,
  "message": "登入成功",
  "data": {
    "token": "eyJhbGciOi...",
    "user": {
      "user_id": "U0001",
      "user_name": "黃惠君",
      "admin": "管理員"
    }
  }
}
測試場景預期 HTTP 狀態預期訊息
正確帳密200登入成功 + 回傳 token
錯誤密碼401使用者 ID 或密碼錯誤
不存在帳號401使用者 ID 或密碼錯誤
停用帳號（inuse_flag=NOUSE）403此帳號已停用，請聯絡系統管理員
無 token 存取受保護 API401尚未登入，請先登入系統

C-3. 管理員權限驗證

# 1. 登入取得 token
TOKEN=$(curl -s -X POST http://localhost:3008/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"user_id":"U0001","password":"68315711"}' | jq -r .data.token)

# 2. 管理員存取使用者管理 API（應回傳 200）
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:3008/api/user | jq .success

# 3. 一般使用者登入並嘗試存取使用者管理（應回傳 403）
TOKEN2=$(curl -s -X POST http://localhost:3008/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"user_id":"U0003","password":"123456"}' | jq -r .data.token)

curl -H "Authorization: Bearer $TOKEN2" \
  http://localhost:3008/api/user

# 預期回應：{"success":false,"code":"FORBIDDEN","message":"你的權限不足，無法進入該功能"}
驗證重點：
  • 管理員（admin='管理員'）可存取 /api/user → 200
  • 普通者（admin='普通者'）存取 /api/user → 403
  • 普通者存取其他業務 API（如 /api/bep/query）→ 200（不受限制）

C-4. 使用者管理功能驗證（瀏覽器）

  1. 開啟瀏覽器前往 http://<伺服器IP>:3008（或 Nginx 網址）
  2. 登入畫面輸入 U0001 / 68315711，點擊「登入」
  3. 登入成功後，頂欄應顯示「👤 黃惠君」與「登出」按鈕
  4. 點擊左側選單「使用者管理」→ 應看到 30 個帳號的列表
  5. 列表應包含以下欄位：帳號、姓名、部門、使用者類別、身分、狀態、建立時間、操作
  6. 點擊任一行「✏️」編輯按鈕 → 彈窗標題應為「編輯使用者」，帳號欄為唯讀
  7. 彈窗應包含：帳號、密碼、狀態、身分（管理員/普通者）、姓名、部門、客戶ID、郵箱、電話、使用者類別（一般員工/部門經理/高階主管）
  8. 修改任一欄位後點擊「儲存」→ 應顯示綠色 toast「已儲存」
  9. 登出後以普通者帳號（如 U0003）登入，點擊「使用者管理」→ 應顯示「🔒 你的權限不足，無法進入該功能」

附錄：故障排除

問題：git pull 時出現 "Permission denied"

# 確認 SSH 金鑰已設定（如果用 SSH 方式）
ssh -T git@github.com

# 或改用 HTTPS 方式
git remote set-url origin https://github.com/rocky1953/ERMM-finance-system.git

問題：npm install 失敗（網路問題）

# 使用淘寶鏡像
npm install --production --registry=https://registry.npmmirror.com

問題：服務啟動後立即 crash

# 查看 PM2 錯誤日誌
pm2 logs ermm-finance --lines 30 --err

# 常見原因：
# 1. .env 檔案缺失或密碼錯誤 → 檢查 DB_PASSWORD（ermm_user / LD*6835755）
# 2. MySQL 未啟動 → systemctl start mysql
# 3. 端口 3008 被佔用 → ss -tlnp | grep 3008

問題：登入回傳 500 內部錯誤

# 1. 確認 cams_xuser 表結構完整
mysql -u ermm_user -p ermm_db -e "DESCRIBE cams_xuser"

# 2. 確認 admin 欄位已遷移
node database/add_admin_column.js

# 3. 確認 email/tel_no/xuser_type 欄位已遷移
node database/add_user_cols.js

# 4. 重啟服務
pm2 restart ermm-finance

問題：瀏覽器顯示舊版頁面（快取問題）

Node.js 已設定 Cache-Control: no-store，但 Nginx 可能仍有快取。解決方式：
  • 瀏覽器按 Ctrl+Shift+F5（或 Cmd+Shift+R）強制刷新
  • Nginx 設定加上：add_header Cache-Control "no-store";
  • 清除 Nginx 快取：rm -rf /var/cache/nginx/*
