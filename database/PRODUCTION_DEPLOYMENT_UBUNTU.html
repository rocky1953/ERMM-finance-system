一、部署架構總覽

使用者瀏覽器 → Nginx :80 / :443
純反向代理（不路由） → Node.js Express :3008
app.js + routes/（全部路由） → MySQL 8 :3306
ermm_db
Redis :6379 / DB 1
會話快取

systemd：ermm-finance.service   mysql.service   redis-server.service   Cron：每日 02:00 備份
設計原則：Nginx 不參與路由分發
Nginx 的 location / 將所有請求（含 /api/*、靜態檔、SPA 前端）統一代理到 Node.js 的 3008 埠。路由分發的職責完全由 app.js 的 app.use('/api/xxx', routes) 和 routes/ 資料夾下的 25 個路由檔承擔。新增功能只需在 Node.js 層加路由檔，Nginx 設定永不改動。

-- 建立資料庫（小寫 ermm_db）
CREATE DATABASE IF NOT EXISTS ermm_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 建立 ermm_app 帳號（僅允許本機連線）

  ON ermm_db.* TO 'ermm_backup'@'localhost';

FLUSH PRIVILEGES;
SQL

十、階段 8：Nginx 反向代理 + HTTPS

核心設計原則：Nginx 只當純反向代理，路由分發全在 Node.js
Nginx 設定只需 location / { proxy_pass http://127.0.0.1:3008; }，所有 /api/* 路由由 app.js 和 routes/ 資料夾管理。新增功能不需要修改 Nginx，只需在 Node.js 層新增路由檔即可。

路由分發架構

層級檔案職責新增功能是否需改
Nginx/etc/nginx/sites-available/ermm-finance反向代理 + HTTPS + 上傳限制不需要
Node.js 入口app.js引入路由檔 + 註冊路徑前綴 + 靜態檔服務加 2 行（require + app.use）
路由邏輯routes/新模組.js定義 GET/POST/PUT/DELETE 端點新增此檔案
前端頁面public/js/pages/新頁面.js呼叫新 API + 渲染 UI新增此檔案

8-1. 安裝 Nginx

apt install -y nginx
systemctl enable --now nginx
nginx -v

8-2. 建立反向代理站台設定

nano /etc/nginx/sites-available/ermm-finance
# ERMM 財務模組 — 純反向代理，路由全在 Node.js
# 先以 HTTP 設定，憑證申請完成後 certbot 會自動改寫為 HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name finance.company.com;          # 改成你的網域

    # Excel 匯入上傳限制
    client_max_body_size 50m;

    # 安全回應標頭
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    # 所有請求統一代理到 Node.js（不在此做路由分發）
    location / {
        proxy_pass http://127.0.0.1:3008;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Excel 批次匯入耗時，逾時拉長至 5 分鐘
        proxy_connect_timeout 60s;
        proxy_read_timeout    300s;
        proxy_send_timeout    300s;
    }
}
# 啟用站台並移除預設站台
ln -s /etc/nginx/sites-available/ermm-finance /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default

# 測試語法並重新載入
nginx -t
systemctl reload nginx

十一、階段 9：MySQL 定時備份

9-1. 備份帳號認證檔

[mysqldump]
user=ermm_backup
password=aaabbb123

chmod 600 /etc/mysql/backup.cnf

9-2. 備份腳本

nano /root/Project/ERMM-finance-system/scripts/db_backup.sh
#!/usr/bin/env bash
# ERMM MySQL 每日備份 + gzip + 保留 14 天
set -euo pipefail

BACKUP_DIR=/var/backups/ermm-mysql
RETENTION_DAYS=14
DB=ermm_db
TS=$(date +%Y%m%d_%H%M)
FILE="$BACKUP_DIR/ERMM_$TS.sql"

mkdir -p "$BACKUP_DIR"

mysqldump \
  --defaults-file=/etc/mysql/backup.cnf \
  --single-transaction \
  --routines --triggers \
  --default-character-set=utf8mb4 \
  "$DB" > "$FILE"

gzip -9 "$FILE"

find "$BACKUP_DIR" -name 'ERMM_*.sql.gz' -mtime +$RETENTION_DAYS -delete

echo "[$(date '+%F %T')] Backup OK: $FILE.gz"
chmod 700 /root/Project/ERMM-finance-system/scripts/db_backup.sh

# 手動試跑一次
/root/Project/ERMM-finance-system/scripts/db_backup.sh
ls -lh /var/backups/ermm-mysql/

9-3. 註冊 Cron 每日 02:00 執行

nano /etc/cron.d/ermm-backup
# ERMM 資料庫每日備份（每天 02:00）
0 2 * * * root /root/Project/ERMM-finance-system/scripts/db_backup.sh >> /var/log/ermm/backup.log 2>&1
chmod 644 /etc/cron.d/ermm-backup
systemctl restart cron

9-4. 備份日誌輪轉

nano /etc/logrotate.d/ermm-backup
/var/log/ermm/backup.log {
    monthly
    rotate 6
    compress
    missingok
    notifempty
    create 0640 root root
}

十五、故障排查

症狀 1：服務啟動失敗

journalctl -u ermm-finance -n 100 --no-pager

# 常見原因：
# ① Cannot find module 'express'  → 未執行 npm install --omit=dev
# ② ENOENT .env / WorkingDirectory → 目錄路徑錯
# ③ Access denied for user          → .env 密碼錯
# ④ EADDRINUSE :3008                → 埠口被佔
# ⑤ Redis connection refused        → Redis 未啟動或密碼錯

症狀 2：Redis 連線失敗

# 確認 Redis 運行
systemctl status redis-server

# 測試連線（帶密碼 + 指定 DB 1）
redis-cli -a aaabbb123 -n 1 ping
# 若回 NOAUTH → .env 的 REDIS_PASSWORD 與 redis.conf 不一致
# 若回 Connection refused → Redis 服務未啟動或 bind-address 不對

症狀 3：3008 埠口被佔用

ss -ltnp | grep :3008
pkill -f "node app.js"
systemctl restart ermm-finance

症狀 4：Nginx 502 Bad Gateway

systemctl status ermm-finance
curl http://127.0.0.1:3008/api/health
tail -20 /var/log/nginx/error.log

症狀 5：Nginx 413 Request Entity Too Large

# 確認 Nginx 設定有：
client_max_body_size 50m;
# 修改後：nginx -t && systemctl reload nginx

症狀 6：中文資料亂碼

mysql -u ermm_app -p ermm_db -e "SHOW VARIABLES LIKE 'character%';"
# 確認 character_set_server = utf8mb4
# mysqldump 與 mysql 導入都需帶 --default-character-set=utf8mb4

症狀 7：重開機後服務沒起來

systemctl is-enabled ermm-finance mysql redis-server nginx
# 若非 enabled：
systemctl enable ermm-finance mysql redis-server nginx
journalctl -u ermm-finance -b --no-pager | head -50
