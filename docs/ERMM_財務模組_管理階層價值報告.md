# ERMM 财务模组 · 管理阶层价值报告

> CEO / 高阶主管 / 部门主管视角 | 2026 Q4 更新

---

## 一、为什么需要这套系统？

### 1.1 老问题：管理阶层长期困扰

| 困扰 | 具体表现 |
|---|---|
| **员工到底有没有在做事？** | 老员工报工时凭良心，主管看不到每日明细，月度汇总拖到次月中才出来，绩效会议没有效数据 |
| **报工时造假无法验证** | 事后补填、连续周六加班无人审核、月报和日报对不上，主管想查却无从查起 |
| **奖惩没有依据** | 迟交、缺交、未解案件的责任人模糊，年底绩效评估只能主观感觉，留不住优秀员工也留不住不合格员工 |
| **目标设定与实际脱节** | 部门目标靠 Excel 手动维护，更新不及时，主管不知道谁达标、谁超标、谁落后 |
| **签核锁定后被改动** | 以前签完字的日报，过几天发现被改了，问谁改的、何时改的、改了什么？没记录 |
| **跨部门协调进度无法追踪** | 采购部迟交物料 → 生产部停线 → 但谁延迟、为什么、解决了没有？主管看到的只是结果，看不到过程 |
| **月底缺报日报无人预警** | 月底才发现有人连续多日未交日报，为时已晚，无法及时补救 |
| **财务入账、报税、对账全靠 Excel** | 凭证、报税表、勾稽关系散落在不同 Excel，数据不一致、追溯困难、月底关账加班 |
| **现金水位无法预判** | 不知道未来 13 周现金余额，无法提前安排融资或付款，安全水位靠拍脑袋 |

### 1.2 核心诉求

> **「我作为 CEO / 主管，要随时看到『现在』公司的状况，而不是看到『上个月』的状况。」**

## 二、系统总览

### 2.1 产品定位

**一套即时、透明、可追溯的企业经营管理平台（ERMM）· 财务模组**

- **即时**：员工提交日报的瞬间，主管就能看到；凭证一入账，报税/勾稽自动关联
- **透明**：每一笔工时、每一张凭证、每一笔税额、每一次修改，全程留痕
- **可追溯**：RUID 贯穿入账→报税→勾稽全链路，谁在什么时间、从哪个 IP、改了什么、为什么改，全部有记录

## 三、功能详解（管理阶层关心什么，系统就展示什么）

### 3.1 📊 提交及时率看板

**CEO 关心**：有多少人准时交报表？谁经常迟交或缺交？

| 指标 | 计算方式 | 管理意义 |
|---|---|---|
| 应交天数 | 当月工作日数（自动排除周六周日） | 基线，公平对比 |
| 实交天数 | 有日报提交的日期数 | 员工出勤诚实度 |
| 准时天数 | 当天 24:00 前提交 | 主动性与纪律 |
| 迟交天数 | 次日补交 | 被动性 |
| 缺交天数 | 当月完全没交 | 严重警讯 |
| **及时率** | 准时天数 ÷ 应交天数 × 100% | **核心 KPI** |

**即时告警**：
- 🟢 ≥ 90% 绿色：表现优异
- 🟠 ≥ 70% 橙色：需关注
- 🔴 < 70% 红色：主管必须介入

**解决的困扰**：
> 以前年底评绩效，员工说「我这一年很努力」，主管只能凭印象。现在打开系统，及时率 96% vs 42%，事实说话。

---

### 3.2 📋 月度绩效汇总

**部门主管关心**：我的团队本月表现如何？谁达标、谁落后？

| 指标 | 内容 |
|---|---|
| 日报天数 | 实际提交日报的天数 |
| 总工时 | 当月所有明细工时加总 |
| 工作占比 | 日常工作 ÷ 总工时（越高越聚焦业务） |
| 生活占比 | 职业发展 / 健康 / 家庭 / 朋友圈 / 休闲等 |
| 日均工时 | 总工时 ÷ 日报天数 |
| 延误笔数 | 当月有「待主管审核 / 跨部门协调」的日报数 |
| 未解笔数 | 当月有「待主管决策 / 后续规划未定案」的日报数 |

**与目标对比**：
- 目标工时 vs 实际工时 → 达成率 %（绿 / 橙 / 红）
- 延误上限 vs 实际延误 → 是否超标
- 未解上限 vs 实际未解 → 是否超标
- 工作占比下限 vs 实际占比 → 是否过度分散

**解决的困扰**：
> 采购部经理说「我的团队这个月很忙」，打开一看：总工时 120h，但生活占比 60%、延误 28 笔超过上限 22 笔 → 原来忙的不是正事。

---

### 3.3 🎯 目标设定与管理

**CEO / 主管关心**：每个人的绩效标准是什么？谁来定？怎么调整？

| 特性 | 说明 |
|---|---|
| **按月设定** | 每人每月 1 条（HR 可按部门批量设定） |
| **4 个维度** | 目标工时 / 延误上限 / 未解上限 / 工作占比下限 |
| **备注说明** | 每个目标可写业务理由（如「采购淡季」「高标挑战月」） |
| **即时生效** | 保存后，月度绩效汇总立即显示达成率变化 |
| **权限控制** | 只有主管能设定 / 修改，员工只能看 |

**解决的困扰**：
> 人事部 A 员工 1 月目标 97h，实际 76h（111% 超额达标）→ 原来设定的是激励目标；而 7 月设定 113h（挑战目标）→ 实际 98.5h（87% 未达标）→ 主管知道这个月要特别关注。

---

### 3.4 📝 签核锁定（逐人 / 整批）

**高阶主管关心**：已签核的日报不能被改动，数据要稳定。

| 特性 | 说明 |
|---|---|
| **两种粒度** | ✅ 逐人锁定（指定某人某月） ✅ 整批锁定（当月全部有日报者，一键完成） |
| **锁定后效果** | 员工无法新增、修改、删除该月任何日报 → HTTP 423 拒绝 |
| **权限制衡** | 部门主管 → **只能锁定，不能解锁**；高阶主管 / 管理员 → **可以解锁，但必须填写原因** |
| **解锁必留痕** | 解锁人 / 时间 / IP / 原因 全部记录到审计日志 |

**解决的困扰**：
> 以前月底主管签完核，有人回头偷偷改自己的日报补满工时 → 现在只要主管一键锁定当月全部，谁也动不了。真要改？先申请解锁、填原因，全公司看得到。

---

### 3.5 📜 审计日志

**高阶主管 / 稽核关心**：谁改了什么？什么时间改的？从哪里改的？

| 记录项目 | 内容 |
|---|---|
| 操作动作 | CREATE 新增 / UPDATE 修改 / DELETE 删除 / LOCK 锁定 / UNLOCK 解锁 |
| 操作人 | 姓名 + 账号 |
| 操作 IP | 来源 IP（含代理后首段） |
| 归属人 | 这笔日报属于谁 |
| 旧值 / 新值 | 完整 JSON 快照（日报主表 + 明细） |
| 备注 | 解锁原因 |
| 时间戳 | 精确到秒 |

**权限分级查看**：
- 一般员工 → 只能看自己的
- 部门主管 → 只能看本部门
- 高阶主管 / 管理员 → 全部

**解决的困扰**：
> 稽核室发现某笔日报工时异常 → 打开审计日志，一秒看到「谁在 2026-09-28 14:32 从 192.168.1.50 把『等待主管审核中』改成『已完成』，旧值是 XXX」。

---

### 3.6 🔒 已锁定月的只读保护

**员工体验**：被锁定的月不是禁止进入，而是标记为只读。

| 效果 | 说明 |
|---|---|
| 列表页 | 🔒 图标 + 浅黄底色，删除按钮自动隐藏 |
| 表单页 | 橙色横幅「本月日报已签核锁定」→ 所有 input 禁用、保存按钮隐藏 |
| API 层 | 后端同时拦截（HTTP 423 Locked），前端绕过也写不进去 |

---

### 3.7 🔔 日报告警引擎（M3）

**CEO / 部门主管关心**：不用等到月底才发现问题，缺报日报能第一时间收到预警。

| 规则 ID | 规则名称 | 触发条件 | 预警级别 |
|---|---|---|---|
| R1 | 连续未交日报 | 连续 ≥3 个工作日未交 → 黄色警告；≥5 天 → 红色危险 | 🟡→🔴 |
| R2 | 工时异常偏高 | 单日工时 >12h 或周工时 >60h | 🟡 |
| R3 | 未解案件积压 | 当月未解笔数 >目标上限 | 🟡 |
| R4 | 延误案件积压 | 当月延误笔数 >目标上限 | 🟡 |
| R5 | 工作占比过低 | 当月工作占比 <目标下限 | 🟡 |

**核心机制**：
- **冷却去重**：同一规则同一员工 12 小时内不重复告警，避免邮件轰炸
- **自动升级**：黄色预警持续未改善 → 自动升级为红色危险
- **自动调度**：工作日 09:30 / 16:30 自动扫描，月末 16:00 执行月度总结扫描
- **邮件通知**：告警同步发送至责任人邮箱
- **可调阈值**：5 条规则的阈值、冷却时间均可在「通知中心」页面调整，支持停用

**解决的困扰**：
> 以前月底才发现采购员 A 连续 8 天没交日报 → 现在第 3 天系统就发黄色警告，第 5 天红色危险邮件直达主管，当天就能介入。

---

### 3.8 📈 趋势预测面板（M3）

**主管关心**：下个月这个员工/部门的工时、延误、未解会怎样？提前干预。

| 能力 | 说明 |
|---|---|
| **混合算法** | WMA（加权移动平均）+ LR（线性回归）融合，历史数据越近权重越高 |
| **80% 置信区间** | 预测值同时给出上下限，让主管看到波动范围 |
| **风险分级** | 🟢 低风险 / 🟡 中风险 / 🔴 高风险（基于预测值是否突破目标阈值） |
| **回测验证** | 以历史月为基准回测，HM 公司 MAPE 平均 12.2% |

**解决的困扰**：
> 主管不用等月底才救火，看预测面板就知道「采购员 A 下月延误笔数预测 22 笔，超过上限 20 笔 → 高风险」，提前谈话或调整目标。

---

### 3.9 📒 会计入账（RUID 全链路）

**财务主管 / 会计关心**：每一张凭证有唯一编号，从入账到报税到对账全程可追溯。

| 特性 | 说明 |
|---|---|
| **RUID 唯一编号** | 格式 `R{BU}{时间戳}{3位随机}`，全局唯一，贯穿凭证→报税→勾稽 |
| **借贷平衡校验** | 借方合计 ≠ 贷方合计 → 拒绝保存，防止错账 |
| **状态机** | 草稿 DRAFT → 提交 SUBMITTED → 审核 APPROVED → 过账 POSTED（或驳回 REJECTED） |
| **科目表** | 内置 18 个常用会计科目，支持扩展 |
| **分录明细** | 每张凭证可挂多条分录，支持借贷多科目 |

**解决的困扰**：
> 以前凭证号手工编，查一笔账要翻好几本 Excel → 现在一个 RUID 就能定位到凭证、分录、关联的报税单和勾稽记录。

---

### 3.10 🧾 纳税申报

**财务主管关心**：每月报税自动算税、自动关联已过账凭证、有回执可查。

| 特性 | 说明 |
|---|---|
| **自动算税** | 增值税 13% / 企业所得税 25% / 印花税 0.03%，输入应税金额自动计算 |
| **自动关联** | 建立申报表时自动关联该期间已过账的入账 RUID，数据链路不断 |
| **状态流转** | 已计算 CALCULATED → 已审核 APPROVED → 已申报 FILED（含模拟税务回执号） |
| **申报明细** | 每张申报表可挂多条应税项目，支持不同税率 |

**解决的困扰**：
> 以前月底报税要从凭证 Excel 手动摘数、算税、填表，容易出错 → 现在系统自动关联已过账凭证，一键算税，申报后有回执号留痕。

---

### 3.11 🔗 勾稽对账

**财务主管 / 稽核关心**：入账金额和报税金额对得上吗？有没有差异？

| 状态 | 含义 | 处理方式 |
|---|---|---|
| MATCHED 匹配 | 入账 RUID 与报税 RUID 金额一致 | 自动标记，无需处理 |
| AMOUNT_DIFF 金额差异 | 关联了但金额对不上 | 差异金额标红，人工核查 |
| UNMATCHED 未匹配 | 有入账无对应报税（或反之） | 标记差异预警，人工处理 |
| HANDLED 已处理 | 人工已处理差异 | 留处理备注 |

**解决的困扰**：
> 以前对账要把凭证表和报税表手动 VLOOKUP，差异要找半天 → 现在一键执行勾稽，系统自动比 RUID、比金额，差异直接标红。

---

### 3.12 📊 报税明细表（年度汇总 + 导出）

**财务主管 / 管理层关心**：全年各税种交了多少税？一键导出成 Excel 给老板看。

| 特性 | 说明 |
|---|---|
| **年度汇总卡片** | 按税种分类展示笔数、应税金额、税额；深蓝卡片显示全年税额合计 |
| **9 列明细表** | 期间 / 税种 / 项目 / RUID / 应税金额 / 税率 / 税额 / 状态 / 回执号，表头吸顶 |
| **一键导出 CSV** | 文件名 `报税明细表_{BU}_{年度}.csv`，带 UTF-8 BOM，Excel 打开不乱码 |
| **CSV 内容** | 标题行 + 全部明细 + 各税种小计 + 全年合计 |

**解决的困扰**：
> 老板要「2025 年交了多少税」的报表 → 以前要翻 12 个月报税单手工加总 → 现在选 2025 年任意月份，点「生成报税明细表」，一秒出汇总，再点导出就是 Excel。

---

### 3.13 💰 13 周现金预测 + 安全水位

**CEO / 财务主管关心**：未来 13 周现金够不够？会不会跌破安全线？

| 特性 | 说明 |
|---|---|
| **13 周滚动预测** | 基于历史现金日记账数据，预测未来 13 周每周现金余额 |
| **安全水位设定** | 每个 BU 可设定安全水位金额（默认：未来每周平均流出 × 3 周，下限 300 万） |
| **跌破预警** | 预测余额低于安全水位 → 该周数据点变红、最低水位卡转红显示「⚠️ 低于安全值」 |
| **图表展示** | 蓝色预计现金曲线 + 橙色安全水位线，一目了然 |

**解决的困扰**：
> 以前 CEO 问「下个月现金够不够发工资」，财务要算半天 → 现在打开 13 周预测图，看橙色安全线和蓝色曲线的关系，跌破线的周次直接标红。

## 四、解痛总结

| 管理痛点 | 系统解决方案 |
|---|---|
| 看不到员工真实工作状态 | 📊 即时提交及时率 + 📋 月度绩效汇总，一秒看到谁在混、谁在冲 |
| 奖惩没有依据 | 📊 及时率 + 📋 绩效指标 + 🎯 目标对比，数据说话不是感觉说话 |
| 签核后被偷偷改动 | 📝 签核锁定（423 硬拦） + 📜 审计日志（改了什么一秒可查） |
| 目标设定混乱 | 🎯 按月逐人设定，4 个维度，备注写理由，保存即生效 |
| 稽核室没有证据 | 📜 每一次操作都有 IP + 时间 + 旧新值快照 |
| 年底绩效会议扯皮 | 月度数据全存在，年度汇总自动生成，谁达标谁落后清清楚楚 |
| 缺报日报月底才发现 | 🔔 日报告警引擎，连续 3 天黄色、5 天红色，自动发邮件 |
| 下月风险无法预判 | 📈 趋势预测面板，WMA+LR 混合算法，80% 置信区间 + 风险分级 |
| 财务入账报税对账靠 Excel | 📒 凭证 + 🧾 申报 + 🔗 勾稽，RUID 贯穿全链路，数据一致可追溯 |
| 老板要年度纳税报表 | 📊 报税明细表一键生成 + CSV 导出，各税种小计 + 全年合计 |
| 现金水位无法预判 | 💰 13 周现金预测 + 安全水位设定，跌破线自动预警 |

## 五、技术保障（给 IT 主管）

| 维度 | 说明 |
|---|---|
| **权限分级** | 员工 / 部门主管 / 高阶主管 / 管理员，每个功能都有权限检查 |
| **事务一致性** | 审计日志与业务操作在同一数据库事务中，改了一定有记录，回滚一定一起回滚 |
| **前端绕过也无效** | 后端每个写操作都重复检查锁定状态，HTTP 423 硬拦 |
| **IP 记录** | 支持 X-Forwarded-For，准确记录操作人来源 |
| **数据保护** | 锁定后的数据只读，解锁需高阶主管 + 原因双条件 |
| **RUID 全链路** | 凭证→报税→勾稽统一编号，任一端的数据异常都能追溯到源头 |
| **告警冷却** | 同规则同人 12h 内不重复发信，避免邮件轰炸 |
| **测试覆盖** | Jest 自动化测试，每次改动全量回归 |
| **语言支持** | 界面支持简体中文 / 繁体中文 / English 三语切换，默认简体中文 |

## 六、使用场景实例

### 场景 1：月底绩效会议

> **CEO** 打开系统 → 选 2025/09 → 看各部门及时率排行榜：人事部 96% 第一，采购部 72% 最后。点进采购部 U0002 的月度汇总 → 总工时 113.5h 达标（105%），但延误 17 笔、未解 23 笔都超过上限。CEO 对采购经理说：「工时不错，但问题处理进度明显落后，下个月目标把未解压到 15 笔以下。」

### 场景 2：日报告警自动介入

> **采购部主管** 周一早上收到系统邮件：「采购员 A 已连续 4 个工作日未交日报（黄色警告）」。主管立即找 A 谈话，A 承认上周在赶供应商对账忘了交。主管提醒后，A 当天补交。如果等到月底，A 可能缺交 20+ 天。

### 场景 3：稽核室调查

> **稽核主管** 收到举报：某人 9 月底的工时异常。打开审计日志 → 搜索 2025/09 + 该员工 → 发现 9 月 30 日 22:15 从 IP 192.168.3.88 有 3 次 UPDATE → 点进去看旧值/新值对比，确认有人深夜改工时补满。稽核主管立即请部门主管锁定 2025/09 全部日报并展开调查。

### 场景 4：月底关账一键勾稽

> **财务主管** 月底关账 → 进入「财务入账／报税 → 勾稽对账」→ 选 2025/09 → 点「执行勾稽」→ 系统返回：匹配 12 笔 / 未匹配 36 笔。未匹配的是收入/成本/费用凭证（无对应报税，属正常口径差异）。主管确认后标记处理，关账完成。

### 场景 5：年度纳税报表给老板

> **老板** 要 2025 年纳税汇总 → 财务打开「报税申报」Tab → 期间选 2025-06 → 点「生成报税明细表」→ 弹窗显示全年税额合计 1,505,071.62 元 → 点「导出 CSV」→ 把 `报税明细表_HM_2025.csv` 发给老板。

### 场景 6：现金安全水位预警

> **CEO** 打开「现金流量预测」→ 看到 13 周预测曲线在第 8 周跌破橙色安全水位线 → 立即要求财务安排短期融资或延迟非必要付款，避免现金断链。

## 七、快速上手

| 身份 | 操作 |
|---|---|
| **部门主管** | 左侧菜单 → 工作日报表 → 列表页看到：📊 及时率 / 📋 绩效汇总 / 🎯 目标 / 📝 签核 / 🔔 通知中心 / 📈 趋势预测 |
| **高阶主管 / 管理员** | 同上 + 解锁权限（填原因）+ 全部审计日志查看 + 告警规则调整 |
| **财务人员** | 左侧菜单 → 财务入账／报税 → 三个 Tab：📒 会计入账 / 🧾 报税申报（含报税明细表导出） / 🔗 勾稽对账 |
| **财务主管 / CEO** | 左侧菜单 → 现金预测 → 13 周水位曲线 + 安全水位设定 |
| **一般员工** | 左侧菜单 → 工作日报表 → 只能看到自己的列表 + 新增 / 修改 / 删除自己的日报 |

## 八、系统架构（给 CTO / IT 主管）

```
┌──────────┐  ┌──────────┐  ┌──────────┐
│  前端 SPA  │  │  Express  │  │  MySQL 8 │
│ (原生 JS) │→│  5 + mysql2│→│  ermm_db │
│ Chart.js  │  │  权限分级  │  │  事务安全 │
└──────────┘  └──────────┘  └──────────┘
                                    ↑
                          ┌─────────┴─────────┐
                          │  daily_report      │
                          │  daily_report_detail│
                          │  daily_report_lock  │  ← 签核锁定
                          │  daily_report_audit │  ← 审计日志
                          │  daily_report_target│  ← 目标设定
                          │  alert_rule         │  ← 告警规则（5条内置）
                          │  alert_log          │  ← 告警记录
                          │  forecast_log       │  ← 趋势预测记录
                          │  fin_voucher        │  ← 会计凭证
                          │  fin_voucher_entry  │  ← 凭证分录
                          │  fin_tax_return     │  ← 纳税申报表
                          │  fin_tax_return_item│  ← 申报明细
                          │  fin_reconciliation │  ← 勾稽对账
                          │  fin_ruid_ledger    │  ← RUID 主台账（全链路中枢）
                          │  fin_account_subject│  ← 会计科目表
                          │  mgm_cash_safe_level│  ← 现金安全水位
                          └────────────────────┘
```

- **端口**：3008 / HTTP
- **部署**：`node database/add_*.js` 建表 → `node app.js` 启动
- **测试**：Jest 自动化用例全量回归
- **默认语言**：简体中文（支持繁/简/英切换）

| 模块 | 数据量 | 说明 |
