> 所屬模組：ERMM 財務模組 / 經營決策  
> 功能編號：P2-04（第 10 項功能）  
> 最後更新：2026-09-23

---

## 一、功能概述

### 1.1 業務目的

高階主管在制定經營決策（如調整售價、擴增產能、調整授信政策、償還借款等）前，需要**事前評估**不同假設情景對關鍵財務指標的衝擊，避免事後才能發現決策失誤。

本功能提供「樂觀 / 基準 / 悲觀」三情景的假設參數設定，基於公司當期實際財務資料，模擬計算 14 項核心財務指標的變動，並以對比表格、圖表與決策建議呈現，輔助主管做出數據驅動的決策。

### 1.2 功能定位

| 維度 | 說明 |
|------|------|
| 使用對象 | 總經理、財務長、經營分析師 |
| 使用時機 | 制定年度預算、重大投資決策、經營策略調整前 |
| 核心價值 | 將「不確定性」量化為可比較的財務指標變動 |
| 與其他功能關係 | 與「現金預測」（外推）、「AI 問答」（查詢）互補，構成「回顧→監控→預測→模擬」閉環 |

### 1.3 功能清單

1. 三情景參數設定（營收成長率、成本變動率、費用率、應收天數變動、借款變動率）
2. 基期財務資料自動載入（依公司別 + 月份）
3. 14 項財務指標衝擊計算
4. 實際值 vs 三情景對比表格
5. 淨利 / 毛利率 / 負債比視覺化對比圖
6. 自動決策建議（依淨利正負、負債比門檻觸發）

## 二、業務流程

### 2.1 主流程

```
使用者進入頁面
    │
    ▼
選擇公司別 + 基期月份（預設 HM / 2025-12）
    │
    ▼
調整三情景參數（可使用預設值）
    │
    ▼
點擊「執行模擬」
    │
    ▼
前端收集 15 個參數（3情景 × 5參數）
    │
    ▼
POST /api/scenario/simulate
    │
    ▼
後端從 mgm_finance_summary 讀取基期資料
    │
    ▼
對三情景分別執行 calcScenario() 計算
    │
    ▼
回傳實際值 + 三情景結果
    │
    ▼
前端渲染：對比表 + 圖表 + 決策建議
```

### 2.2 流程-程式-資料對照表

| 步驟 | 前端入口 | 請求介面 | 後端方法 | 讀寫表 | 關鍵欄位 |
|------|---------|---------|---------|--------|---------|
| 載入頁面 | `registerPage('scenario')` | — | — | — | 預設參數寫死在 HTML |
| 設定參數 | 5×3 個 `<input>` | — | — | — | opt_rev / base_rev / pes_rev 等 |
| 執行模擬 | `Scenario.run()` | `POST /api/scenario/simulate` | `router.post('/simulate')` → `getBaseData()` + `calcScenario()` ×3 | **讀** `mgm_finance_summary` | sale_amt, sale_cost_amt, sale_exp_amt, MGM_EXP_amt, finance_EXP_amt, net_profit_amt, AR_amt, loan_amt, ttl_asset_amt, ttl_debet_amt, stockholder_amt, cash_amt, deposite_amt |
| 渲染結果 | `Scenario.render()` | — | — | — | actual / scenarios.optimistic / scenarios.base / scenarios.pessimistic |

> **說明**：本功能為純讀取+計算，不寫入任何資料表。所有模擬結果僅在記憶體中計算並回傳前端，不持久化。

## 四、核心計算邏輯（欄位級）

計算引擎位於 `routes/scenario.js` 的 `calcScenario(base, params)` 函式。以下為每個輸出指標的計算公式與資料來源。

### 4.1 輸入參數（使用者設定）

| 參數 | 代碼變數 | 單位 | 預設（樂/基/悲） |
|------|---------|------|-----------------|
| 營收成長率 | `revenueGrowth` | % | 15 / 5 / -10 |
| 成本變動率 | `costGrowth` | % | 5 / 5 / 8 |
| 費用率 | `expenseRate` | % | 18 / null / 25 |
| 應收天數變動 | `arDaysChange` | 天 | -10 / 0 / 15 |
| 借款變動率 | `loanChange` | % | -20 / 0 / 10 |

### 4.2 基期資料來源（`mgm_finance_summary`）

| 基期變數 | 來源欄位 | 說明 |
|---------|---------|------|
| `sale` | `sale_amt` | 營業收入 |
| `cost` | `sale_cost_amt` | 銷售成本 |
| `saleExp` | `sale_exp_amt` | 銷售費用 |
| `mgmtExp` | `MGM_EXP_amt` | 管理費用 |
| `finExp` | `finance_EXP_amt` | 財務費用 |
| `opExp` | 上述三項合計 | 營業費用 |
| `ar` | `AR_amt` | 應收帳款 |
| `loan` | `loan_amt` | 短期借款 |
| `asset` | `ttl_asset_amt` | 資產總額 |
| `debt` | `ttl_debet_amt` | 負債總額 |
| `equity` | `stockholder_amt` | 股東權益 |
| `cash` | `cash_amt + deposite_amt` | 現金+約當現金 |

### 4.3 輸出指標計算公式

| 輸出欄位 | 計算公式 | 說明 |
|---------|---------|------|
| `revenue` | `sale × (1 + revenueGrowth/100)` | 模擬營收 |
| `cost` | `cost × (1 + costGrowth/100)` | 模擬成本 |
| `gross_profit` | `revenue - cost` | 毛利 |
| `gross_margin` | `gross_profit / revenue × 100` | 毛利率（%） |
| `operating_expense` | 見下方「費用規則」 | 營業費用 |
| `operating_profit` | `gross_profit - operating_expense` | 營業利益 |
| `net_profit` | `operating_profit × 0.8` | 稅後淨利（簡化稅率 20%） |
| `net_margin` | `net_profit / revenue × 100` | 淨利率（%） |
| `accounts_receivable` | `ar × (1 + arDaysChange/60)` | 應收帳款（以60天為基準週期） |
| `cash` | `cash + cashDelta` | 現金餘額（見下方「現金衝擊」） |
| `total_asset` | `asset + ΔAR + Δinventory + Δcash` | 資產總額 |
| `total_debt` | `debt + Δloan` | 負債總額 |
| `debt_ratio` | `total_debt / total_asset × 100` | 負債比率（%） |
| `roe` | `net_profit / newEquity × 100` | 股東權益報酬率（%） |

### 4.4 關鍵規則

#### 規則 1：費用計算雙模式

```
若 expenseRate !== null（使用者指定費用率）：
    operating_expense = revenue × expenseRate / 100
否則（expenseRate === null，依營收比例）：
    baseExpRate = opExp / sale   （基期費用率）
    operating_expense = revenue × baseExpRate
```

**設計意圖**：允許使用者直接指定目標費用率（如費用控制專案），或維持現有費用結構隨營收等比例變動。

#### 規則 2：應收帳款與天數關聯

```
accounts_receivable = ar × (1 + arDaysChange / 60)
```

**設計意圖**：假設基期應收週轉天數為 60 天（2 個月）。若縮短 10 天（arDaysChange=-10），則應收餘額減少 10/60≈16.7%，釋出現金。

#### 規則 3：存貨簡化假設

```
inventory = asset × 0.2    （存貨佔資產 20%）
newInventory = inventory × (1 + inventoryChange / 100)
```

> **注意**：`inventoryChange` 參數目前在前端未提供輸入框，固定為 0（存貨不變）。後端已保留擴展點。

#### 規則 4：現金衝擊計算

```
cashDelta = (newSale - sale)           // 營收變動帶來的現金
          - (newCost - cost)           // 成本變動消耗的現金
          - (newOpExp - opExp)         // 費用變動消耗的現金
          + (ar - newAR)               // 應收減少釋出現金
          + (newLoan - loan)           // 借款增加帶來現金
```

**設計意圖**：現金變動 = 營業活動現金流 + 應收變動 + 融資活動現金流。簡化模型，未考慮投資活動與稅費實際現金流出時點。

#### 規則 5：稅後淨利簡化

```
net_profit = operating_profit × 0.8
```

**設計意圖**：簡化稅率為 20%（營利事業所得稅），未考慮虧損扣抵、境外稅額扣抵等複雜情境。

#### 規則 6：股東權益變動

```
newEquity = equity + (net_profit - base.net_profit_amt)
```

**設計意圖**：假設當期淨利變動全數影響保留盈餘，未考慮股利發放、資本公積變動。

### 4.5 邊界條件與防護

| 情境 | 處理方式 | 程式位置 |
|------|---------|---------|
| `sale === 0`（基期無營收） | 毛利率、淨利率回傳 0，避免除零 | `calcScenario` L48, L57, L85, L89 |
| `expenseRate === null` | 採用基期費用率模式 | `calcScenario` L54 |
| `newAsset <= 0` | 負債比回傳 0 | `calcScenario` L94 |
| `newEquity <= 0` | ROE 回傳 0 | `calcScenario` L95 |
| 找不到基期資料 | 回傳 `fail` 錯誤 | `/simulate` L106 |
| 缺少 `bu_no` 或 `YYYY_MM` | 回傳 `fail` 錯誤 | `/simulate` L103 |

| 情景 | 條件 | 建議文字 |
|------|------|---------|
| 樂觀 | `debt_ratio < actual.debt_ratio` | 「負債比下降，財務結構改善」 |
| 樂觀 | 否則 | 「需關注負債水準」 |
| 基準 | （固定） | 「維持現有經營假設下的預期結果」 |
| 悲觀 | `net_profit < 0` | 「⚠️ 可能虧損，需啟動降本措施」 |
| 悲觀 | `debt_ratio > 70` | 「⚠️ 負債比超過 70%，財務風險升高」 |
| 悲觀 | 否則 | 「需嚴控成本與費用」 |

## 八、常見修改場景指引

### 場景 1：新增模擬參數（如「存貨變動率」前端輸入）

1. **前端** `scenario.js` 參數表格新增一列 `<input id="opt_inv" ...>`，三情景各一個
2. **前端** `Scenario.run()` 的 scenarios 物件新增 `inventoryChange: num('opt_inv')`
3. **後端** `calcScenario()` 已支援 `inventoryChange` 參數（L29, L67-68），無需改動
4. 後端已預設 `inventoryChange` 從 params 解構，只需確保前端有傳值

### 場景 2：調整稅率（目前 0.8 = 20%）

1. **後端** `routes/scenario.js` L62：`const netProfit = opProfit * 0.8;`
2. 改為 `const netProfit = opProfit * (1 - TAX_RATE);` 並定義常數 `const TAX_RATE = 0.2;`
3. 前端不須改動

### 場景 3：新增輸出指標（如「每股盈餘 EPS」）

1. **後端** `calcScenario()` return 物件新增欄位，如 `eps: netProfit / totalShares`
2. **後端** `baseResult` 物件同步新增
3. **前端** `Scenario.render()` 的 `row()` 呼叫新增一列
4. 如需在圖表顯示，於 Chart.js datasets 新增

### 場景 4：變更應收基準天數（目前 60 天）

1. **後端** `routes/scenario.js` L65：`const newAR = ar * (1 + arDaysChange / 60);`
2. 改為從 `mgm_finance_summary` 實際計算基期應收週轉天數：`baseARDays = ar / sale * 30`（假設月度）
3. 公式改為 `newAR = ar * (1 + arDaysChange / baseARDays)`

### 場景 5：儲存模擬方案

1. 新增資料表 `scenario_saved`（uid, bu_no, YYYY_MM, scenario_name, params_json, result_json, created_by, created_at）
2. 新增路由 `POST /api/scenario/save`、`GET /api/scenario/saved`
3. 前端新增「儲存方案」按鈕與方案列表

## 九、已知限制與後續優化

| 項目 | 現況 | 建議優化 |
|------|------|---------|
| 稅率 | 固定 20% | 依公司別實際稅率或虧損扣抵調整 |
| 存貨 | 假設佔資產 20% | 從 `mgm_finance_summary` 的 stock_* 欄位實際計算 |
| 應收基準天數 | 固定 60 天 | 用基期實際應收週轉率換算 |
| 折舊 | 未納入 | 可加入 `acc_de_*` 欄位計算非現金費用 |
| 多期模擬 | 單期 | 支援年度滾動（12 個月連續模擬） |
| 方案儲存 | 不支援 | 新增 `scenario_saved` 表 |
| 敏感度分析 | 單參數 | 支援單變數敏感度（龍捲風圖） |
