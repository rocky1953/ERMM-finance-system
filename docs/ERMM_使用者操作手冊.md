# ERMM 智能财务管理平台 · 使用者操作手册

> 适用版本：v3.5（2026-11-15）｜适用对象：全体员工、部门主管、高阶主管、管理员
> 系统地址：http://localhost:3008 ｜浏览器：Chrome / Edge
> 每个操作单元均含三部分：**目的**（为什么做）、**前置条件**（做之前要什么）、**操作步骤**（每步的功能说明）。

# 1. 登录与界面导航

## 1.1 登录系统

- **目的**：验证身份、获取 JWT 会话凭证，并按角色加载权限。
- **前置条件**：管理员已在「用户管理」建立账号。
- **操作步骤**：
  1. 打开 `http://localhost:3008` —— 系统自动显示登录页（未登录状态全站锁定）。
  2. 输入**工号**（如 S10049）与**密码** —— 提交后后端校验 `cams_xuser`，签发 JWT 存入浏览器 localStorage。
  3. 登录成功自动进入**仪表板** —— 右上角显示当前用户姓名；此后所有 API 请求由前端自动携带 `Authorization: Bearer <token>`。
- **说明**：JWT 过期或失效时，任意操作触发 401，系统自动清除会话并回到登录页。

## 1.2 界面导航

- **目的**：在 67 个功能入口（8 个分组）之间切换，并切换公司/月份上下文。
- **操作步骤**：
  1. 左侧**侧边栏菜单**共 8 个分组：仪表板 / 经营决策 / ERP 原始单据 / 日常作业·工作日报 / 财务分析·税务申报 / 财务预警·KPI 查询 / 系统·主档管理 / 系统文件 —— 点击即切换页面，路由由前端 `navigate()` 管理。「系统文件」整组仅管理员可见，非管理员实际显示 7 个分组。
  2. 顶部**公司切换**（HM / SZ / HN）—— 切换后所有页面数据按 `bu_no` 重新取数。
  3. 顶部**月份选择**（YYYY-MM）—— 决定报表、日报、报税的所属期间。
  4. 语言切换（简/繁/英）—— 全站 i18n 即时生效，默认简体中文（`zh-CN`），选择结果保存在浏览器，下次登录沿用。
- **说明**：
  - `bu_no` 与 `YYYY_MM` 是全局状态（State），贯穿所有 API 查询参数。
  - 点击左上角 **🏢 ERMM** 标志可打开**系统架构图**（与「系统文件」中的架构文档同源）。
  - 菜单项是否显示由「系统 · 主档管理 → **功能权限**」的模块矩阵控制（见 **13.4**），默认值见附录 A。
  - 「**使用者管理**」菜单固定**仅管理员（admin='Yes'）可见**；「**系统文件**」分组默认仅管理员可见（如需开放给高管，可在 13.4 勾选操作员列）。非管理员即使手动输入地址，也会被拦截并提示「你的权限不能使用这个模块功能」。
  - **看不到的菜单＝你的角色没有该模块权限**：菜单按「功能权限」矩阵渲染，未勾选的模块直接不显示；即使绕过前端直接调用对应的 `/api/xxx`，后端模块守门也会回 `403`（`MODULE_DENIED`），不会返回数据。
  - **权限变更无需重登**：管理员调整矩阵后，你按 `F5` 刷新页面，或切换到其他窗口再切回来（系统会自动同步权限），菜单即按新矩阵显示；当前页面若无权限，会自动跳转到你有权限的第一个页面。

## 1.3 登出

- 点击右上角头像 → **登出** —— 清除本地 token 并呼叫 `/api/auth/logout` 记录登出日志。

# 2. 仪表板（经营驾驶舱）

## 2.1 查看 KPI 与图表

- **目的**：一屏掌握当月收入、成本、利润、资产负债与风险灯号。
- **操作步骤**：
  1. 进入「仪表板」—— 顶部 KPI 卡片展示当月关键指标（数据来源 `/api/kpi`）。
  2. 左侧**损益图**（收入 vs 成本柱体）、右侧**资产负债图**（数据来源 `/api/summary`）。
  3. 下方**风险面板**展示 5 条预警规则的扫描结果（绿/黄/红灯）。

## 2.2 柱体下钻查明细

- **目的**：从汇总数字一键钻取到发票级明细，回答「这个数字由哪些单据构成」。
- **操作步骤**：
  1. 点击损益图的**收入柱体** —— 弹窗列出当月全部**销项发票**（客户、金额、税额、合计）。
  2. 点击**成本柱体** —— 弹窗列出当月全部**进项发票**（供应商、金额、税额、合计）。
  3. 弹窗底部显示合计行 —— 与柱体金额必须一致（数据勾稽的可视化验证）。
- **说明**：数据来源 `/api/invoice?bu_no=&YYYY_MM=&TX_type=`；明细与财报同源（`mgm_invoice_details`）。

## 2.3 KPI 红灯异常诊断

- **目的**：指标异常时自动给出 Top3 原因与改善建议。
- **操作步骤**：
  1. 点击变红的 KPI 卡片 —— 系统呼叫 `/api/diagnosis/kpi`。
  2. 弹窗展示：当期值 vs 门槛、较上期变化、Top3 原因（维度/影响/建议）。
  3. 点击 Z-Score 卡片可查看评分公式与区间说明。

## 2.4 每日 AI 执行摘要

- **目的**：每天开工前用一段自然语言摘要掌握「昨天发生了什么、今天要盯什么」，省去逐页翻报表。
- **前置条件**：系统已配置 LLM 服务商（预设为 DeepSeek，可在 `/api/llm/providers` 查询当前预设）。
- **操作步骤**：
  1. 仪表板上方展示**每日 AI 摘要卡片** —— 内容取当日/最近一次生成结果（`/api/daily-summary/latest`）。
  2. 点击**「重新生成」** —— 系统读取财务摘要、预警、收付款等数据后呼叫 LLM 生成，结果写入 `daily_ai_summary`。
  3. 点击**「历史」** —— 按日期回看往日摘要，用于复盘（`/api/daily-summary/history`）。
- **说明**：摘要为**辅助阅读**，数字口径仍以报表页为准；生成失败时卡片会提示原因，不影响其他页面。

# 3. 工作日报表（填报 / 审核 / 锁定）

## 3.1 员工填报日报

- **目的**：逐日记录工作内容与工时，沉淀人效数据。
- **前置条件**：当天未被锁定（`daily_report_lock`）。
- **操作步骤**：
  1. 进入「工作日报表」→ 选择日期 → **新增明细行** —— 填写项目、内容、工时。
  2. **保存草稿** —— 写入 `daily_report` + `daily_report_detail`，可反复修改。
  3. **提交签核** —— 状态流转为「待审」，此后本人不可再改（防止事后篡改）。

## 3.2 主管审核

- **目的**：确认下属日报真实性，形成管理闭环。
- **操作步骤**：
  1. 主管进入日报页 → 切换「待审核」页签 —— 列表仅显示其部门成员（权限过滤）。
  2. 点击**通过 / 退回** —— 通过则状态「已核准」；退回附原因，员工可修改后重提。
  3. 每次签核动作写入 `daily_report_audit_log`（操作人、IP、时间、前后状态）。

## 3.3 月度锁定

- **目的**：月结后封存数据，保证绩效与财务口径一致。
- **操作步骤**：
  1. 管理员/高阶主管选择月份 → **锁定** —— 写入 `daily_report_lock`。
  2. 锁定后任何修改请求返回 **HTTP 423 Locked** —— 硬约束，前端与后端双重拦截。
  3. 如需调整：**解锁**（需高阶权限），操作同样留痕。

# 4. 财务入账与 RUID 勾稽

## 4.1 录入凭证（RUID 全链路）

- **目的**：每笔业务生成唯一 RUID，贯穿凭证 → 账簿 → 报表 → 税表，可追溯。
- **操作步骤**：
  1. 进入「财务入账」→ **新增凭证** —— 填科目、借贷金额、摘要；系统校验借贷平衡。
  2. 保存后生成 **RUID** 并写入 `fin_ruid_ledger`（主台账）与 `fin_voucher`。
  3. 在台账页可按 RUID 反查全链路轨迹（凭证、过账、报表归属、税务归属）。

## 4.2 勾稽核对

- **目的**：验证「业务单据 ↔ 凭证 ↔ 报表」三方一致。
- **操作步骤**：
  1. 进入「勾稽核对」页 —— 系统自动比对发票合计、凭证合计、财报栏位。
  2. 差异行红色高亮 —— 点击行查看差异构成，定位漏记/重记。

# 5. 三大财务报表

- **目的**：按月输出损益表、资产负债表、现金流量表，数据源于 `mgm_finance_summary`。
- **操作步骤**：
  1. 进入「财务报表」→ 选择公司与月份 → 切换三个页签。
  2. **资产负债表**页签顶部显示平衡校验标识：✅ 平衡 / ❌ 不平衡（资产 = 负债 + 权益，精确到分）。
  3. 报表右上角可**导出 CSV** —— 带 BOM，Excel 直接打开不乱码。
- **说明**：当前三账套 2023-2025 共 108 个月报表 100% 平衡；若出现不平衡请联系管理员核查源数据。

# 6. 电子化报税（VAT / CIT / IIT）

> 入口：「税务申报」页，内含 **VAT / CIT / IIT / 申报记录** 四个 Tab。

## 6.1 VAT 增值税申报（Tab 1）

- **目的**：按月（一般纳税人 13%）或按季（小规模 3%）计算应纳税额并生成申报表。
- **操作步骤**：
  1. 选择月份 → 点击**「算税」** —— 系统自动汇总当期销项/进项发票（`mgm_invoice_details`），计算应纳税额 = 销项 − 进项 + 进项转出 − 留抵。
  2. 查看**取数明细区** —— 销项/进项逐笔列出，可核对每张发票；小规模纳税人自动判定 30 万免征阈值。
  3. **栏位点击钻取** —— 算税结果表中「🔍 銷售額合計 / 銷項稅額 / 進項稅額（可抵扣）/ 上期留抵稅額」四个蓝色栏位可直接点击，弹窗显示对应发票明细（发票号/金额/税率/税额 + 合计）；小规模纳税人弹窗自动按 3% 征收率口径展示、进项显示「不可抵扣」，与算税结果保持一致。
  4. 如有特殊事项，在**调整区**录入「进项转出 / 留抵」—— 写入 `tax_vat_adjustments`，点击**重算**生效。
  5. 确认无误点击**「提交税局申报」** —— 生成受理号并写入 `vat_declarations` + `tax_submit_receipts`。
  6. 点击**勾稽核对**（`/api/tax/vat/reconcile`）—— 申报数 vs 账载发票合计比对，差异亮红。
- **税率来源**：一般纳税人税率与小规模征收率读取系统码表 `TAX_TYPE`（码值 `CIT` = 一般纳税人、`IIT` = 小规模纳税人，取 `value_number1`），管理员维护码值即可调整，无需改程序（服务端缓存 1 小时）。

## 6.2 CIT 企业所得税汇算（Tab 2）

- **目的**：年度汇算清缴，财报利润 ± 纳税调整 × 25%。
- **操作步骤**：
  1. 选择年度 → **算税** —— 自动取全年财报收入/成本/费用，计算应纳税所得额与应纳税额。
  2. 若审计调整与账面不同，在**人工覆盖区**录入调整后收入/成本（`tax_cit_inputs`），调整事项（招待费调增等）录入 `tax_cit_adjustments` → **重算**。
  3. 提交申报 —— 写入 `cit_annual_settlements` + 回执。
- **说明**：覆盖前/覆盖后双值留痕，供稽查举证。企业所得税税率读取码表 `TAX_TYPE` 中 `EIT` 的 `value_number1`（预设 25%），码表无值时回退 25%。

## 6.3 IIT 个人所得税（Tab 3）

- **目的**：工资按月累计预扣；年终奖支持单独/并入双通道自动选优。
- **操作步骤**：
  1. 先维护**薪酬明细**（`payroll_details`）与**奖金明细**（`bonus_details`）—— 可逐笔录入或批量导入。
  2. 选择月份 → **算税** —— 系统按累计预扣法（7 级累进）逐人计算当月预扣税额。
  3. 年终奖月份：系统同时计算 **SEPARATE**（÷12 找月度税率）与 **COMBINED**（并入综合所得边际税额）两种结果，自动标注**节税更优方案**。
  4. 提交申报 —— 写入 `iit_withholding_batches` + `iit_withholding_details` + 回执。

## 6.4 申报记录（Tab 4）

- **目的**：集中查询历史申报与受理回执。
- **操作步骤**：
  1. 按税种/期间/状态筛选 —— 列表展示受理号、提交人、时间、金额。
  2. 点击行查看申报快照（提交时的完整计算结果 JSON）。
- **说明**：⚠️ 当前提交链路为**本地模拟受理**（未接真实税局 API），受理号格式与留档机制已就绪，对接后沿用。

# 7. 现金流预测（13 周 + 概率模拟）

## 7.1 13 周滚动预测

- **目的**：预测未来 13 周现金流入/流出，守住安全水位。
- **操作步骤**：
  1. 进入「现金流预测」—— 系统按在手 AR/AP、历史回款周期生成 13 周滚动预测表。
  2. 查看**水位线** —— 低于安全水位的周次红色警示。
  3. 调整假设（回款天数、付款计划）→ 重算，做 What-if 推演。

## 7.2 概率预测（Monte Carlo）

- **目的**：点估计只能给一个数字，概率预测回答「这个月现金不够用的可能性有多大」。
- **操作步骤**：
  1. 进入「现金预测」页 → 顶部模式切换选择 **Monte Carlo 概率带** —— 图表由单线变为 P10 / P50 / P90 区间带。
  2. 查看**概率风险卡** —— 展示未来 13 周内出现负现金的概率、最差周次与缺口金额。
  3. 切换回「点估计」可对比基础预测线，判断乐观/悲观差异。
- **说明**：数据来源 `/api/cash-forecast/monte-carlo`，采用 5000 次模拟（按历史回款波动抽样），仅覆盖已有数据的公司期间。

# 8. 预算与管理会计

## 8.1 预算编制与达成追踪

1. 进入「预算管理」→ 选择年度 → 按部门/科目录入预算 —— 保存后按月拆分。
2. 「预算达成」页自动比对实际数（财报取数）vs 预算数，达成率红黄绿灯。
3. **目的**：让预算从「年初编一次」变为「每月滚动追踪」。

## 8.2 管理会计（部门损益）

1. 进入「管理会计」→ 选择月份 —— 查看各部门收入/成本/毛利分摊。
2. **目的**：看清哪个部门赚钱、哪个部门烧钱，支撑资源调配。

## 8.3 多维盈利分析（客户 / 产品 / 渠道 / 项目）

- **目的**：从「公司赚不赚钱」下钻到「谁贡献利润、哪个产品拖后腿」，为定价、客户结构与渠道投放提供依据。
- **前置条件**：当期有销售订单（SO）数据；未维护渠道/成本率时系统用默认规则估算。
- **操作步骤**：
  1. 侧边栏「经营决策」→ **多维盈利** → 选择公司，切换范围**「本月 / 全年」**。
  2. 切换维度页签：**客户 / 产品 / 渠道 / 项目** —— 表格展示收入、成本、毛利、毛利率、净利与占比，默认按毛利贡献排序。
  3. 点行末**「🔍 下钻」** —— 查看该维度键对应的单据明细与成本构成。
  4. **客户**页签点**「改渠道」** —— 选择渠道（直销 / 经销 / 出口 / 集团 / 其他）并保存；后续分析按新渠道归集，可恢复默认。
  5. **产品**页签点**「设成本率」** —— 输入 0~1 的成本率并保存，用于缺少采购价的料件；点**「清除」**恢复按公司成本率估算。
- **说明**：只读分析，不回写账务；成本优先级为「PO 加权采购均价 → 料件成本率 → 公司销售成本率」。

## 8.4 滚动预算与三表联动

- **目的**：把预算从「年初一张静态 Excel」变成「改一个假设、三张表自动重算」的滚动预测，并同步输出 13 周现金。
- **前置条件**：`mgm_finance_summary` 已有该账套最近实际月数据（否则无基准、无法预测）。
- **操作步骤**：
  1. 侧边栏「经营决策」→ **滚动预算** → 选择公司，选择滚动期数（**12 / 18 / 24 个月**）。
  2. 进入**「假设参数」**页签 —— 核对系统按最近 3 个月实际数推导的基准值，按需修改：月收入增长率、销售成本率、所得税率、应收/应付/存货天数、每月资本支出、每月还本金额。
  3. 点**「保存假设并重算」** —— 三表与 13 周现金按新假设立即重算。
  4. 切换**「损益表 / 资产负债表 / 现金流量表」** —— 查看逐月预测与合计；资产负债表底部**「平衡差额」应接近 0**，否则核对期初与假设参数。
  5. 切换**「13 周现金」** —— 查看周度余额曲线与最低现金点；低于安全水位（默认 300 万）会标红。
- **说明**：预测只读、不写账务；基准月默认取最新实际月，实际数更新后重新进入页面或点「🔄 刷新」即可。

# 11. 第三方资料整合（Excel / SQL）

> 入口：「资料整合」页，内含 **5 个 Tab**：📊 Excel 导入 / 🔌 SQL 线上整合 / ⏰ 批次作业 / 🗄️ 数据源 / 📜 执行日志，整页支持简/繁/英三语。

## 11.1 Excel 导入（Tab 1）

- **目的**：业务人员自助把 Excel 数据并入系统，无需 IT 写脚本。
- **前置条件**：明确要写入的目标资料表；建议先下载系统模板，避免栏位名不符。
- **操作步骤**：
  1. 选择**目标资料表** —— 下拉列出 `ermm_db` 内全部表（含中文表注释）。
  2. 点击**「下载本表模板」** —— 系统按该表栏位动态生成 xlsx 表头（也可点「下载全表模板」取得总模板）。
  3. 上传 `.xlsx`（单档 ≤ 20MB）→ 选择 **Sheet** —— 系统用 ExcelJS 解析并预览前 5 行与总行数。
  4. **栏位映射** —— 同名栏位自动匹配，可手动调整；系统实时校验目标栏位是否存在于白名单（防注入）。
  5. 选择**写入模式**（INSERT 新增 / UPSERT 依唯一键更新）→ 点击执行。
  6. 执行结果写入 `intg_log`，可在「执行日志」Tab 查看新增/更新/失败行数。
- **说明**：日期、千分位数字、空值会自动清洗；每批 200 行写入，失败行不影响已成功批次。

## 11.2 SQL 线上整合（Tab 2）

- **目的**：直接从第三方 MySQL 库抽取数据，或先预览再决定是否落库。
- **前置条件**：已在「数据源」Tab 建好第三方连线（或本页新建并测试通过）。
- **操作步骤**：
  1. 选择**数据源** → 输入一条 **SELECT** 查询 → 点击**测试读取**预览结果（最多 100 行，前端默认取 50 行）。
  2. 选择**目标资料表**后，可点「**📋 複製欄位清單**」复制目标表全部字段（栏位名 / 备注 / 类型 / 是否必填）；或点「**⚡ 生成 SQL 语句**」一键生成完整查询语句，自动填入「② 第三方查询 SQL」栏位。生成规则：列出目标表全部非自增字段并带 `AS` 别名；若原 SQL 已有 `FROM`，沿用其 `FROM/WHERE`，否则以目标表名为来源表并补 `WHERE 1 = 1`。
  3. 完成**栏位映射**（可沿用预设唯一键）。
  4. 点击**立即执行**写入本地表；或点**存为批次作业**，转由排程自动执行。
- **说明**：仅允许单条 SELECT、禁止多语句，系统自动包成子查询并强制 `LIMIT`，第三方库只读访问。使用「生成 SQL 语句」后，请确认语句中的 `FROM` 表名与实际第三方表一致，再点「测试读取」。

## 11.3 批次作业（Tab 3）

- **目的**：把 SQL 整合配置保存为可重复执行的作业，按排程自动同步。
- **操作步骤**：
  1. 查看**作业清单** —— 显示数据源、目标表、排程、启用状态与上次执行结果。
  2. **启用 / 停用** —— 停用后不再被排程触发，配置保留。
  3. **编辑** —— 调整 SQL、映射、排程（`daily HH:mm` 每日定时或 `every Nm` 每 N 分钟）。
  4. **立即执行** —— 手动跑一次（Online）。
  5. **失败重试** —— 上次状态为 `FAIL` 的作业会显示「重试」按钮，一键重跑。
- **说明**：排程器每分钟 tick，具备防重入（同一作业同一时刻只跑一份）与防重复触发机制。

## 11.4 数据源（Tab 4）

- **目的**：集中管理第三方 MySQL 连线。
- **操作步骤**：
  1. **新增数据源** —— 填名称、主机、端口、库名、账号、密码。
  2. **测试连接** —— 保存前可先预检；保存后也可随时再测。
  3. **编辑 / 删除** —— 删除时系统同步关闭并释放该数据源的连接池。
- **说明**：每个数据源的连接池按 `sourceId` 缓存复用，避免反复握手。

## 11.5 执行日志（Tab 5）

- **目的**：追溯每次导入/同步的结果，快速定位失败原因。
- **操作步骤**：
  1. 进入「执行日志」—— 默认显示最近 100 条记录。
  2. 按**状态**（SUCCESS / FAIL / RUNNING）或**通道**（SQL / Excel）筛选。
  3. 查看每条的作业名、触发方式（排程 / 手动 / Excel）、目标表、总行数、新增/更新/失败行数、耗时与错误信息。
  4. 点击**导出 CSV** —— 将当前筛选结果导出（UTF-8 BOM，Excel 直接打开不乱码）。

# 12. 财务预警 / KPI 查询（YG001~YG004）

> 菜单分组「財務預警 / KPI 查詢」，包含 YG001~YG004 四个页面，构成「指标定义 → 预警监控 → 异常甄别 → 趋势预测」的完整风控闭环。

## 12.1 YG001 KPI 预警指标

- **目的**：集中查看所有 KPI 的当期预警状态，让管理者一眼看出「哪些指标亮红灯」。
- **功能**：展示各 KPI 的当期值、门槛值、灯号（绿/黄/红），数据来源于预警引擎对 5 条预警规则的扫描结果（工作日 09:30 / 16:30 由 node-cron 自动执行）。
- **操作步骤**：
  1. 进入「YG001 KPI 预警指标」—— 列表按灯号排序，红灯指标排最前。
  2. 查看每项 KPI 的**当期值 vs 门槛值** —— 判断是否真实异常或阈值设置过严。
  3. 点击红灯指标 —— 联动跳转 YG003 报表异常甄别，查看 Top3 原因。
- **说明**：触发预警时系统同时以邮件（nodemailer）通知责任人，无需人工盯屏。

## 12.2 YG002 KPI 指标管理

- **目的**：维护 KPI 定义与预警阈值，让预警规则随经营策略调整。
- **功能**：KPI 的新增/编辑/停用——定义指标名称、计算公式、取数来源、门槛值、责任人与通知方式。
- **操作步骤**：
  1. 进入「YG002 KPI 指标管理」→ **新增指标** —— 填名称、公式、门槛（如毛利率下限 30%）。
  2. **编辑**既有指标 —— 调整阈值或责任人；修改即时生效于下一次扫描。
  3. **停用**不再适用的指标 —— 保留历史数据但不再扫描。
- **前置条件**：高阶主管或管理员权限。
- **说明**：阈值改得太松会漏警、太严会滥警，建议参考过去 6 个月实际波动区间设定。

## 12.3 YG003 报表异常甄别

- **目的**：指标异常时自动定位原因，回答「为什么超标、该找谁」。
- **功能**：对异常 KPI 自动下钻分析，输出 Top3 原因（维度归属、影响量化、改善建议），含 Z-Score 评分说明。
- **操作步骤**：
  1. 进入「YG003 报表异常甄别」（或从 YG001 / 仪表板红灯 KPI 点入）。
  2. 查看**当期值 / 门槛 / 较上期变化** —— 确认异常幅度。
  3. 阅读 **Top3 原因卡片** —— 每张卡含维度、描述、影响金额、改善建议。
  4. 按建议分派改善行动，次月同一页面验证异常是否消除。
- **说明**：数据来源 `/api/diagnosis/kpi`；建议由规则引擎产出，重大异常仍需人工复核。

## 12.4 YG004 预测模型分析

- **目的**：基于历史数据预测未来 3 / 6 / 12 个月经营趋势，支撑事前决策。
- **功能**：对收入、成本、利润等核心指标做趋势外推，展示预测曲线与置信区间。
- **操作步骤**：
  1. 进入「YG004 预测模型分析」→ 选择指标与预测期间（3 / 6 / 12 个月）。
  2. 查看**预测曲线图** —— 历史实线与预测虚线对比，拐点一目了然。
  3. 结合 YG001 预警结果 —— 若预测下行且当期已亮黄灯，提前启动应对预案。
- **说明**：数据来源 `/api/forecast`；预测基于历史趋势，突发市场变化需人工修正判断。

# 13. 系统管理与个人设置

## 13.1 用户管理（管理员）

1. 「用户管理」→ 新增/编辑用户 —— 设置工号、姓名、部门、**使用者类别**（员工 / 部门主管 / 部门经理 / 高阶主管）与**身份**（管理员 / 操作员 / 普通用户，对应 `admin = Yes / Operator / No`）。
2. 两个字段分工不同，**不要混用**：
   - **身份**：只有 `admin = Yes` 才拥有管理员权限；`Operator` 仅为身份标识，不单独决定模块权限。
   - **使用者类别**：决定动作级权限（能否新增 / 审批 / 查看他人数据），并参与模块矩阵的「操作员」判定（类别含「主管」或「经理」即按操作员处理）。
3. 重置密码、停用账号；登录日志（`login_user_record`）可查。
4. 菜单可见性不在此页配置，见 **13.4 权限配置**。

## 13.2 系统码维护

- **目的**：集中维护全站下拉选项与业务参数，改配置不改代码。
- **操作步骤**：
  1. 「系统管理」→「系统码维护」—— 左侧按 `code_type` 分类，右侧列出码值。
  2. **新增 / 编辑码值** —— 填写 `code_value`（码值）、`value_description`（显示名称）、`value_number1~3`（数值型参数，如税率/汇率）、启用标志与排序。
  3. **停用 / 删除** —— 停用后该码值不再出现在业务下拉中，历史数据不受影响。
  4. 查看 `schema_migrations` 可确认数据库迁移版本。
- **常用码表**：`BUSINESS_ID`（公司账套 HM/SZ/HN）、`TAX_TYPE`（VAT/CIT/IIT/EIT 税率）、`CURRENCY`（汇率）、`WK_TYPE`（工作类型）、`USER_ROLE`（角色）等。
- **生效时间**：前端刷新页面后读取新码值；服务端缓存 TTL 为 1 小时，税率等参数最迟 1 小时内生效（重启服务可立即生效）。调整税率后如马上算税，请先重启服务或等待缓存过期。

## 13.3 个人操作

- 右上角修改本人密码；切换语言；查看当前会话信息。

## 13.4 权限配置（🔐 功能权限）

- **入口**：系统 · 主档管理 → **功能权限**；改完点 **保存**。
- **权限模型（三层叠加，缺一层就会出现「菜单有但操作被拒」或反之）**：

| 层级 | 控制什么 | 配置位置 | 判定依据 |
|---|---|---|---|
| ① 模块可见性 | 左侧菜单是否出现、页面能否打开 | 本页「功能权限」 | `cams_module_permission` × 角色列 |
| ② 动作权限 | 能否新增 / 编辑 / 删除 / 审批 / 看他人数据 | 用户管理 + 各业务接口 | 使用者类别、身份 |
| ③ 数据范围 | 只看本部门 / 本公司数据 | 各业务列表接口 | 用户部门 + 顶部公司切换 `bu_no` |

- **角色判定规则**（页面保存三列，用户登录后按下列顺序落到其中一列）：
  1. `admin = Yes` → **管理员**（代码硬编码全权限，矩阵不限制其访问）；
  2. 否则**使用者类别**含「主管」或「经理」（部门主管 / 部门经理 / 高阶主管）→ **操作员**列；
  3. 其余（员工等）→ **一般**列。
  > 注意：身份选 `Operator` 只是标识，不单独决定矩阵列；矩阵列由使用者类别判定。
- **页面结构**：
  1. 顶部「公司别 / 月份 / 语言」是全站上下文切换器，**不影响**矩阵内容——矩阵全站统一，不分公司、不分期间。
  2. 按 8 个分组展示，组标题显示模组数量：**仪錶板（1）/ 经营决策（23）/ ERP 原始单据（6）/ 日常作业（20）/ 财务分析（11）/ 财务预警（4）/ 系统主档（9）/ 系统文件（7）**，共 **81 个模组**。
  3. 每行一个模组：**功能模组名称 + 模组代码**（如 `dashboard`、`expense`、`docManualCeo`）+ **一般 / 操作员 / 管理员** 三个勾选框。
- **配置步骤（以新员工上线为例）**：
  1. 用户管理建账号：设部门、**使用者类别**、身份（普通员工 = 员工 / `No`）。
  2. 本页找到其角色列，勾选该岗位需要的模组（如 `expense` 费用报销、`dailyReport` 工作日报、`approvals` 审批待办）。
  3. 点 **保存** → 通知用户重新登录或刷新页面，菜单即按新矩阵显示。
- **批量操作**：
  1. 单个模组：直接勾选 / 取消该角色列。
  2. 整组批量：点列头 **全选 / 取消** —— 设置「该分组 × 该角色」下全部模组。
  3. 按角色整组批量：点分组右上角 **一般全部选 / 一般取消 / 操作员全部选 / 操作员取消 / 管理员全部选 / 管理员取消**。
  4. **取消** 按钮放弃未保存修改，不影响已生效配置。
- **生效规则**：
  - 保存即写库；已在线的用户**刷新页面、或切回窗口（焦点自动同步，30 秒节流）**即按新矩阵显示，无需重新登录（权限判定缓存 60 秒内到期）。
  - 无权限页面即使手动输入地址也会被拦截，提示「你的权限不能使用这个模块功能」；直接调用无权限模块的 API 会返回 **403 `MODULE_DENIED`**。
  - 权限变更**无需重启服务**，也不会改动任何单据数据。
- **常见配置场景**：

| 场景 | 配置动作 |
|---|---|
| 只让财务人员看报销与付款 | 一般列取消无关项，保留 `expense` / `payRequest` / `approvals` / `arMatch` |
| 新任命部门主管 | 使用者类别改为「部门主管」，再在操作员列补齐其所需模组 |
| 收回某模块 | 对应角色列取消勾选并保存，用户刷新或切回窗口后菜单消失（最慢 60 秒） |
| 向高管开放文档 | 系统文件默认仅管理员；如需开放，勾选操作员列对应文档模组 |
| 临时停用某人 | 用户管理中把 `inuse_flag` 置为停用，比逐项取消权限更干净 |

- **注意事项**：
  - 管理员恒可访问全部模块，矩阵对其不生效（避免把自己锁死）；「管理员」列用于记录与后续扩展。
  - 「功能权限」页面自身仅管理员可见。
  - 本页只控制可见性，不改审批流走向；审批人仍由流程设定（18.2）决定。

# 14. 智能化功能（AI 赋能）

> 本章 5 个功能构成系统的「智能层」：**知识问答、自动摘要、催收排序、数据体检、概率预测**。
> 全部功能均为**只读分析**，不会自动修改账务数据；如需修正请回到对应业务页面操作。

## 14.1 AI 智能问答（RAG）

- **目的**：用自然语言提问（如「本月毛利率为什么下降」「发票丢了怎么补」），系统检索内部知识库后给出有依据的回答，免去翻文档。
- **前置条件**：已登录；知识库由管理员维护（`ermm_knowledge`，当前 41 条 / 6 个分类：年度 / 政策 / 税务 / 基准 / 数据字典）。
- **操作步骤**：
  1. 侧边栏「经营决策」→ **AI 问答** —— 进入对话界面。
  2. 在输入框提问，或点击页面下方的**建议问题**（系统按当期数据动态生成）。
  3. 回答下方展示**引用来源**（命中的知识条目），可点开核对原文；若知识库无匹配，会明确告知「未找到依据」并记入未命中日志。
  4. 左侧可查看**历史会话**，按会话继续追问（多轮上下文保留）。
  5. 页面上方显示的「🧠 DeepSeek（預設）」为**唯读**——服务商由管理员在「系统设定 → LLM 服务商管理」指定（标记 ★ 预设的那一家），使用者在此不能切换，也不提供 API Key 管理入口。
- **说明**：后端为 `/api/aiqa/ask`；勾选 LLM 后服务商一律取自 `llm_config` 中 `is_default=1 AND status='USE'` 且有 API Key 的记录（无预设时取第一家可用的 USE 服务商），前端不再传 provider；未配置任何服务商时提示管理员前往 LLM 服务商管理新增。检索采用 n-gram 关键词滑窗 + 分类加权（税务 ×1.5 / 数据字典 ×1.3 / 政策 ×1.2 / 基准 ×1.0 / 年度 ×0.8）。回答仅供决策参考，涉及金额以报表为准。

## 14.2 AR 智能催收（应收优先级排序）

- **目的**：把手上一堆应收账款按「该先催谁」排序，把催收精力放在最该催的单据上。
- **前置条件**：`mgm_invoice_details` 中存在 `TX_type='AR'` 的发票明细（含账龄天数）。
- **操作步骤**：
  1. 侧边栏「日常作业」→ **AR 智能催收** —— 顶部显示各风险等级的笔数与金额概览。
  2. 查看**催收清单** —— 每条按综合评分排序，展示账龄天数、逾期天数、金额、客户与等级灯号。
  3. 按灯号分层处理：
     - 🔴 **紧急**（评分 ≥ 70）—— 当日联系，必要时暂停发货
     - 🟠 **高优先**（50~70）—— 本周内跟进
     - 🟡 **常规**（30~50）—— 按常规节奏提醒
     - 🟢 **正常**（< 30）—— 无需主动催收
  4. 切换公司（HM / SZ / HN）查看各账套的催收清单。
- **说明**：评分 = 账龄天数 40% + 逾期天数 30% + 金额规模 15% + 风险综合 10% + 单笔占比 5%，数据来源 `/api/ar-smart/collections`；清单只做排序建议，不自动发送催收函。

## 14.3 数据质量自动扫描

- **目的**：上线前一键体检，提前发现「报表数字不对」的根因（脏数据 / 缺失 / 重复 / 逻辑冲突），而不是等出报表才发现。
- **前置条件**：无，任意登录用户可执行扫描。
- **操作步骤**：
  1. 侧边栏「日常作业」→ **数据质量扫描** —— 点击**「开始扫描」**。
  2. 扫描约数十毫秒返回，页面按 **7 大类**展示结果：
     - 财务摘要（6 项）· 发票（5 项）· 银行贷款（3 项）· 现金（1 项）· 预测（2 项）· 勾稽（1 项）· 数据表健康度（8 张核心表）
  3. **红色问题项**为高风险（如报表不平衡、金额为空、重复单据），黄色为提示项；点击问题卡片可查看受影响的记录数与样例。
  4. 按问题类型分别修正：数据缺失 → 补录；重复 → 在业务页面作废；金额异常 → 核对源单据后由管理员修正。
- **说明**：接口 `/api/data-quality/scan`；当前版本为**只扫描不自动修复**，修复仍需人工确认，避免误改历史账。

## 14.4 系统文件（管理员专用）

- **目的**：随时查阅系统的架构说明与数据表关系，不必回开发环境找文件。
- **前置条件**：**admin = Yes** 的账号（如 `rocky`）。非管理员登录后，「系统文件」分组在左侧菜单中**直接隐藏**。
- **操作步骤**：
  1. 侧边栏最下方**「系统文件」**分组，共 **7 项**：
     - 🗺️ **系统架构与流程图** —— 技术栈、API 模块地图、5 大核心数据流程
     - 📊 **高管价值简报** —— CEO / CFO / COO / CTO 价值总览
     - 🗄️ **模块数据表关系图** —— 表总览、ER 图、模块 × 数据表对照、索引与迁移顺序
     - 📘 **CEO / CFO / CTO / COO 操作手册**（4 份）—— 各角色日常操作与决策指引
  2. 点击后在新标签页打开文档页面。
  3. 非管理员：菜单不显示；若透过旧缓存或手动方式访问，页面右下角仍会弹出红色提示「**你的权限不能使用这个模块功能**」，不打开文档。
- **说明**：文档由系统 3008 端口直接提供（`/docs/architecture`、`/docs/executive`、`/docs/data-model`、`/docs/manual-ceo`、`/docs/manual-cfo`、`/docs/manual-cto`、`/docs/manual-coo`）；也可从左上角 🏢 ERMM 标志打开系统架构图。

# 15. 库存周转与呆滞处理

- **目的**：回答三个问题——库存压了多久（库龄）、转得快不快（周转率 / DSI）、谁该处理（呆滞清单与处理单）。
- **前置条件**：`e2_xitems_daily_status` 有该账套的库存日快照；无快照时页面无法取库龄。
- **页面结构**：顶部选择公司与**库存快照日期**（默认选料件行数最多的最近日期），下方 5 个页签。

## 15.1 周转概览

1. 进入「经营决策」→ **库存周转** → 默认打开**「周转概览」**。
2. 查看 KPI：库存金额、周转率（次/年）、周转天数（DSI）、呆滞金额与占比。
3. 下方查看库存金额与 DSI 趋势、存货结构（原料 / 在制 / 成品 / 商品）。

## 15.2 库龄结构

1. 切换**「库龄结构」**页签 —— 按 **0–30 / 31–90 / 91–180 / >180 天** 四档查看金额与占比。
2. 下钻查看各档料件明细（料号、名称、数量、库存金额、库龄天数、快照日期）。

## 15.3 呆滞清单

1. 切换**「呆滞清单」**页签 —— 系统自动列出**库龄 > 90 天**的料件，按库存金额与库龄排序。
2. 每行显示料号、名称、库龄、库存金额、快照日期，并提供**「下发处理」**按钮。

## 15.4 下发处理单

1. 在呆滞清单（或补货建议）行末点**「下发处理」**。
2. 弹窗中确认只读信息（库存金额、库龄），填写：
   - **处置方式**（必填）：降价促销 / 退货供应商 / 报废核销 / 转用在制品 / 暂停采购 / 调拨其他公司
   - 处置数量、预计回收金额、优先级（高/中/低）、责任人、完成时限、备注
3. 点**「确认下发」** —— 生成处理单，状态为**「待处理」**。
4. 到**「处理记录」**页签跟踪：可直接下拉切换**待处理 → 进行中 → 已完成**；误建可点「删除」。
- **说明**：库龄与库存金额来自快照，只读；系统仅在「下发处理」时写入处理单表，不改库存账。

## 15.5 补货建议

1. 切换**「补货建议」**页签 —— 按「交期天数 + 安全天数」计算补货点，结合近 12 个月需求给出建议补货量与紧急度。
2. 需求优先取销售订单（SO）未交量；无 SO 时以采购订单（PO）采购量近似。
3. **说明**：建议为参考值，实际下单仍需结合在途、MOQ 与资金安排判断。

# 16. 费用报销与借支核销（CFO-01）

> 菜单位置：**日常作业** → **费用报销**。页面含「我的报销 / 待我审批 / 借支管理 / 全部报销（主管、管理员）」四个页签。

## 16.1 新建与提交报销单

- **目的**：把个人垫付的费用按公司流程申请报销，形成可审批、可付款、可追溯的单据。
- **前置条件**：已登录；费用类型由码表 `EXPENSE_TYPE` 提供。
- **操作步骤**：
  1. 进入「费用报销」，点右上角 **＋ 新建报销**。
  2. 填写 **报销事由**（必填）、**费用类型**、**公司（BU）**、**备注**。
  3. 在「费用明细」逐条点 **＋ 新增明细**，填写：**费用日期、类别、说明、金额（必填）、发票号、税额**；页面右下角自动汇总**合计**。
  4. 点 **保存草稿** 或 **保存并提交**（提交会生成审批实例并流转到审批人）。
  5. 在「我的报销」列表可 **查看 / 编辑 / 提交审批**；`PENDING` 状态可 **撤回**；`APPROVED` 后由管理员点 **标记付款** 转 `PAID`。
- **说明**：`DRAFT` / `REJECTED` 才能编辑；只有草稿可删除；单号格式 `BX+日期+序号`。

## 16.2 审批费用报销

1. 切换到 **「待我审批」** 页签（或直接到「审批中心」，见第 18 章）。
2. 列表显示单号/事由、申请人、金额、当前步骤（第 N/M 步）、提交时间。
3. 点 **审批** → 在弹窗查看明细 → 选择 **通过** 或 **驳回**，可填写审批意见。
4. 全部步骤通过后单据转 `APPROVED`，退回本人后转 `REJECTED` 可修改重提。

## 16.3 借支管理（预支与核销）

- **目的**：出差/采购等场景先借款、后凭票核销，避免个人大额垫资。
- **操作步骤**：
  1. 点 **＋ 新建借支**，填写 **借支事由（必填）、借支类型（差旅借支 / 一般借支 / 备用金）、公司、借支金额（>0）、预计报销/归还日、备注**。
  2. 保存草稿或保存并提交；单号格式 `JK+YYYYMMDD+序号`。
  3. 审批通过（`APPROVED`）后，由**管理员**在借支行点 **拨付**，状态转 `PAID`，同时生成可核销余额 `balance`。
  4. 后续在借支行点 **核销**：
     - 填写 **核销金额**（必须 ≤ 当前余额）、可**关联报销单**、备注；
     - 提交后写入 `exp_advance_settle` 并扣减余额；
     - 余额仍 > 0 保持 `PAID`，余额归零自动转 `SETTLED`。
  5. 点 **查看** 可展开历史核销记录（核销人、金额、关联报销单、时间）。
- **权限**：拨付仅管理员；核销允许管理员或部门主管。他人无权查看/编辑你的借支单。

# 17. 资金与付款审批（CFO-02）

> 菜单位置：**日常作业** → **付款申请**。页签：**我的付款申请 / 待我审批 / 全部单据（主管、管理员）/ 付款排程（主管、管理员）**。

## 17.1 新建付款申请

1. 点 **＋ 新建付款申请**，填写表头：**付款类型、收款方（pay_target）、公司、币别、付款方式、到期日、备注**。
2. 在「付款明细」逐条新增：**供应商、付款类型、发票号、发票日期、金额**；合计自动回写 `total_amount`。
3. 保存草稿或保存并提交；单号格式 `PK+YYYYMM`。
4. 状态机：`DRAFT → PENDING → APPROVED → PAID`，异常分支 `REJECTED / CANCELLED`。
   - `DRAFT` / `REJECTED` 可编辑；仅草稿可删除；
   - `PENDING` 可由申请人**撤回**（转 `CANCELLED`）；
   - `APPROVED` 后由管理员 **标记付款**（无回单的快捷通道）。

## 17.2 付款排程（按月）

- **目的**：按计划付款日编排资金，提前看到当月应付笔数与金额。
- **前置条件**：主管或管理员。
- **操作步骤**：
  1. 切换到 **「付款排程」** 页签，选择月份（默认当月）。
  2. 顶部汇总卡显示：**计划笔数 / 计划金额 / 已付笔数·金额 / 待付笔数·金额**（按 `PAID` 与其余状态拆分）。
  3. 每行显示单号、收款方、类型、金额、状态、计划付款日、银行回单、核销状态。
  4. 点 **设置排程** 修改**计划付款日**（已 `PAID` / `CANCELLED` 的单据不可改）。
- **说明**：排程只影响资金计划视图，不改变审批与付款状态。

## 17.3 银行回单登记

1. 在 `APPROVED` 状态的付款单行点 **登记回单**。
2. 填写：**银行回单号（必填）、回单日期、回单金额、开户行/付款账户**。
3. 提交后：状态自动转 **`PAID`**，写入 `bank_receipt_no / receipt_date / receipt_amount`，并回写审批实例状态。
4. **说明**：非管理员无权登记；`DRAFT`/`PENDING` 不可登记；`PAID` 后不可再改排程。

## 17.4 AR / AP 核销

- **目的**：把实际付款（或收款）与发票逐笔勾销，随时知道哪些发票已付清、哪些还挂着。
- **前置条件**：付款单为 `PAID`；核销来源为 `sub_amt > payment` 的未付清发票。
- **操作步骤**：
  1. 在付款单行点 **核销**。
  2. 选择来源类型 **AP（应付）/ AR（应收）**，可按公司、关键字（发票号/客户/订单号）检索。
  3. 勾选发票并填写 **核销金额**（累计不得超过发票未付金额）。
  4. 提交后写入 `pay_writeoff`，并重算付款单 `writeoff_status`：
     - 未核销 → `UNWRITTEN`；部分 → `PARTIAL`；累计 ≥ 付款总额 → `WRITTEN`。
  5. 点 **核销记录** 查看明细，误操作可 **撤销**（自动重算核销状态）。
- **说明**：非管理员不能撤销；发票不存在或超额核销会被拦截（400）。

## 23.1 指标中心总览

- **目的**：所有 KPI 指标统一入口，消除散落在仪表板/战情看板/经营分析的重复计算口径。
- **操作步骤**：
  1. 进入「指标中心」—— 列表展示 23 个指标，按 7 类别分组：
     - 🔴 盈利能力：ROE · ROA · 毛利率 · 净利率 · 资产报酬率
     - 💧 流动性：流动比率 · 速动比率 · 现金比率
     - 💪 偿债能力：资产负债率 · 利息保障倍数
     - 🔄 运营效率：存货周转天数 DSI · 应收账款周转天数 DSO · 应付账款周转天数 DPO · 总资产周转率

  3. 点指标卡 → 查看计算公式与血缘追踪（数据来自哪些表、哪些字段）。

## 23.2 ROE 统一口径说明

> **ROE（净资产收益率）= 净利润 ÷ 平均股东权益**
> - 净利润 = `fin_tax_return`（CIT 申报中 `actual_revenue - actual_cost`）
> - 股东权益 = `mgm_finance_summary` 的 `equity + retained_earnings`（(期初 + 期末) / 2）
> - 三账套统一口径，消除之前分散在各页面各自计算导致的口径不一致。

## 23.3 调整指标阈值（管理员）

- **前置条件**：管理员权限。
- **操作步骤**：
  1. 指标卡右上角点 **⚙️ 阈值** —— 弹窗调整：绿灯区间、黄灯区间、红灯预警门槛。
  2. 保存后即时生效（`services/metricCenter.js` 下次计算读取新阈值）。
  3. 所有指标计算走**统一引擎**：`services/metricCenter.js` 提供 `calc(metricCode, bu_no, period)` 方法，前端各页面统一调用，避免重复 SQL。

## 附录 C：常见问题

| 问题 | 处理 |
|---|---|
| 操作中被弹回登录页 | JWT 过期，重新登录即可 |
| 日报无法修改（423） | 该月已锁定，联系高阶主管解锁 |
| 报表不平衡红字 | 联系管理员核查 `mgm_finance_summary` 源数据 |
| 算税结果与预期不符 | 先用「取数明细」核对发票，再查调整区录入 |
| 提交申报后想撤回 | 模拟受理不产生外部效力，联系管理员在申报记录中作废 |
| 非管理员看不到「使用者管理」「系统文件」菜单 | 正常权限控制：使用者管理固定仅管理员可见；系统文件默认仅管理员，可在「功能权限」勾选操作员列开放（见 13.4） |
| 管理员也看不到上述菜单 | 浏览器缓存了旧版 `app.js`，按 `Ctrl+Shift+R` 硬刷新后重新登录 |
| 在「功能权限」勾选后用户仍看不到菜单 | ① 用户未刷新 / 未切回窗口（权限 30 秒节流同步、后端缓存 60 秒）；② 勾错了角色列——矩阵列按使用者类别判定（主管 / 经理 → 操作员，其余 → 一般），不是按身份 `Operator`；③ 该模块是否已登记（如 `contracts` / `audit` 需 Migration 059） |
| 改了功能权限要不要重启服务 | 不需要，保存即写库；用户重新登录或刷新页面即可生效 |
| AI 问答回答「未找到依据」 | 知识库未收录该主题，请联系管理员补充 `ermm_knowledge` 条目 |
| 每日 AI 摘要卡片空白或报错 | LLM 服务商未配置或调用失败，请管理员检查 LLM 设定与网络 |
| AR 智能催收清单为空 | 当期无 `TX_type='AR'` 的发票明细，或所选公司无应收数据 |
| 多维盈利毛利率明显异常 | 先看该行成本口径：有 PO 采购价时按加权均价；否则按料件成本率或公司成本率估算，可在产品页签「设成本率」修正 |
| 多维盈利点「改渠道」保存无效 | 确认该客户有当期销售数据；渠道选项来自 `cams_system_codes`，缺失请联系管理员补码 |
| 滚动预算页面无预测数据 | 该账套在 `mgm_finance_summary` 无实际月数据；先执行批次管线 Step 7 生成财务汇总 |
| 滚动预算资产负债表平衡差不为 0 | 属期初推导差异，核对假设参数与期初现金/存货/权益；差异持续偏大请联系管理员核查源数据 |
| 库存周转页无库龄数据 | 该账套在所选日期无 `e2_xitems_daily_status` 快照，切换快照日期或先跑批次管线 |
| 呆滞清单 / 补货建议为空 | 当前快照无库龄 > 90 天料件；补货建议需有近 12 个月 SO 出库或 PO 采购需求 |
| 下发处理报错（400） | 检查处置方式是否已配置、处置数量/回收金额是否为数字、必填项是否完整 |
| Excel 导入提示「栏位不存在」 | 表头与目标表栏位不一致，先点「下载本表模板」按模板表头填写 |
| 执行日志导出的 CSV 打开乱码 | 文件已带 UTF-8 BOM，请用 Excel 直接打开；若仍乱码请勿用记事本另存为 ANSI |
| 改了码表但页面/算税未变 | 刷新页面；服务端缓存 TTL 1 小时，必要时重启服务立即生效 |
