# ERMM 智能财务管理平台 · 使用者操作手册

> 适用版本：v3.3（2026-11-12）｜适用对象：全体员工、部门主管、高阶主管、管理员
> 系统地址：http://localhost:3008 ｜浏览器：Chrome / Edge
> 每个操作单元均含三部分：**目的**（为什么做）、**前置条件**（做之前要什么）、**操作步骤**（每步的功能说明）。
> 本版新增：第三方资料整合 5 Tab 操作台（Excel 模板动态生成 / 日志筛选导出 / 失败重试）、税率与下拉改由系统码表 `cams_system_codes` 驱动、三语界面（简/繁/英，默认简体）。
> 既有功能：AI 智能问答（RAG）、每日 AI 执行摘要、AR 智能催收、数据质量自动扫描、现金流概率预测（Monte Carlo）、系统文件（管理员专用）。

# 1. 登录与界面导航

## 1.1 登录系统

- **目的**：验证身份、获取 JWT 会话凭证，并按角色加载权限。
- **前置条件**：管理员已在「用户管理」建立账号。
- **操作步骤**：
  1. 打开 `http://localhost:3008` —— 系统自动显示登录页（未登录状态全站锁定）。
  2. 输入**工号**（如 S10049）与**密码** —— 提交后后端校验 `cams_xuser`，签发 JWT 存入浏览器 localStorage。
  3. 登录成功自动进入**仪表板** —— 右上角显示当前用户姓名；此后所有 API 请求由前端自动携带 `Authorization: Bearer <token>`。
- **说明**：JWT 过期或失效时，任意操作触发 401，系统自动清除会话并回到登录页。

## 1.2 界面导航

- **目的**：在 50 个功能入口（8 个分组）之间切换，并切换公司/月份上下文。
- **操作步骤**：
  1. 左侧**侧边栏菜单**共 8 个分组：仪表板 / 经营决策 / ERP 原始单据 / 日常作业·工作日报 / 财务分析·税务申报 / 财务预警·KPI 查询 / 系统·主档管理 / 系统文件 —— 点击即切换页面，路由由前端 `navigate()` 管理。
  2. 顶部**公司切换**（HM / SZ / HN）—— 切换后所有页面数据按 `bu_no` 重新取数。
  3. 顶部**月份选择**（YYYY-MM）—— 决定报表、日报、报税的所属期间。
  4. 语言切换（简/繁/英）—— 全站 i18n 即时生效，默认简体中文（`zh-CN`），选择结果保存在浏览器，下次登录沿用。
- **说明**：
  - `bu_no` 与 `YYYY_MM` 是全局状态（State），贯穿所有 API 查询参数。
  - 点击左上角 **🏢 ERMM** 标志可打开**系统架构图**（与「系统文件」中的架构文档同源）。
  - 「系统文件」分组**仅管理员可见可用**：非管理员点击时弹出「你的权限不能使用这个模块功能」，不会跳转。

## 1.3 登出

- 点击右上角头像 → **登出** —— 清除本地 token 并呼叫 `/api/auth/logout` 记录登出日志。

# 2. 仪表板（经营驾驶舱）

## 2.1 查看 KPI 与图表

- **目的**：一屏掌握当月收入、成本、利润、资产负债与风险灯号。
- **操作步骤**：
  1. 进入「仪表板」—— 顶部 KPI 卡片展示当月关键指标（数据来源 `/api/kpi`）。
  2. 左侧**损益图**（收入 vs 成本柱体）、右侧**资产负债图**（数据来源 `/api/summary`）。
  3. 下方**风险面板**展示 5 条预警规则的扫描结果（绿/黄/红灯）。

## 2.2 柱体下钻查明细

- **目的**：从汇总数字一键钻取到发票级明细，回答「这个数字由哪些单据构成」。
- **操作步骤**：
  1. 点击损益图的**收入柱体** —— 弹窗列出当月全部**销项发票**（客户、金额、税额、合计）。
  2. 点击**成本柱体** —— 弹窗列出当月全部**进项发票**（供应商、金额、税额、合计）。
  3. 弹窗底部显示合计行 —— 与柱体金额必须一致（数据勾稽的可视化验证）。
- **说明**：数据来源 `/api/invoice?bu_no=&YYYY_MM=&TX_type=`；明细与财报同源（`mgm_invoice_details`）。

## 2.3 KPI 红灯异常诊断

- **目的**：指标异常时自动给出 Top3 原因与改善建议。
- **操作步骤**：
  1. 点击变红的 KPI 卡片 —— 系统呼叫 `/api/diagnosis/kpi`。
  2. 弹窗展示：当期值 vs 门槛、较上期变化、Top3 原因（维度/影响/建议）。
  3. 点击 Z-Score 卡片可查看评分公式与区间说明。

## 2.4 每日 AI 执行摘要

- **目的**：每天开工前用一段自然语言摘要掌握「昨天发生了什么、今天要盯什么」，省去逐页翻报表。
- **前置条件**：系统已配置 LLM 服务商（预设为 DeepSeek，可在 `/api/llm/providers` 查询当前预设）。
- **操作步骤**：
  1. 仪表板上方展示**每日 AI 摘要卡片** —— 内容取当日/最近一次生成结果（`/api/daily-summary/latest`）。
  2. 点击**「重新生成」** —— 系统读取财务摘要、预警、收付款等数据后呼叫 LLM 生成，结果写入 `daily_ai_summary`。
  3. 点击**「历史」** —— 按日期回看往日摘要，用于复盘（`/api/daily-summary/history`）。
- **说明**：摘要为**辅助阅读**，数字口径仍以报表页为准；生成失败时卡片会提示原因，不影响其他页面。

# 3. 工作日报表（填报 / 审核 / 锁定）

## 3.1 员工填报日报

- **目的**：逐日记录工作内容与工时，沉淀人效数据。
- **前置条件**：当天未被锁定（`daily_report_lock`）。
- **操作步骤**：
  1. 进入「工作日报表」→ 选择日期 → **新增明细行** —— 填写项目、内容、工时。
  2. **保存草稿** —— 写入 `daily_report` + `daily_report_detail`，可反复修改。
  3. **提交签核** —— 状态流转为「待审」，此后本人不可再改（防止事后篡改）。

## 3.2 主管审核

- **目的**：确认下属日报真实性，形成管理闭环。
- **操作步骤**：
  1. 主管进入日报页 → 切换「待审核」页签 —— 列表仅显示其部门成员（权限过滤）。
  2. 点击**通过 / 退回** —— 通过则状态「已核准」；退回附原因，员工可修改后重提。
  3. 每次签核动作写入 `daily_report_audit_log`（操作人、IP、时间、前后状态）。

## 3.3 月度锁定

- **目的**：月结后封存数据，保证绩效与财务口径一致。
- **操作步骤**：
  1. 管理员/高阶主管选择月份 → **锁定** —— 写入 `daily_report_lock`。
  2. 锁定后任何修改请求返回 **HTTP 423 Locked** —— 硬约束，前端与后端双重拦截。
  3. 如需调整：**解锁**（需高阶权限），操作同样留痕。

# 4. 财务入账与 RUID 勾稽

## 4.1 录入凭证（RUID 全链路）

- **目的**：每笔业务生成唯一 RUID，贯穿凭证 → 账簿 → 报表 → 税表，可追溯。
- **操作步骤**：
  1. 进入「财务入账」→ **新增凭证** —— 填科目、借贷金额、摘要；系统校验借贷平衡。
  2. 保存后生成 **RUID** 并写入 `fin_ruid_ledger`（主台账）与 `fin_voucher`。
  3. 在台账页可按 RUID 反查全链路轨迹（凭证、过账、报表归属、税务归属）。

## 4.2 勾稽核对

- **目的**：验证「业务单据 ↔ 凭证 ↔ 报表」三方一致。
- **操作步骤**：
  1. 进入「勾稽核对」页 —— 系统自动比对发票合计、凭证合计、财报栏位。
  2. 差异行红色高亮 —— 点击行查看差异构成，定位漏记/重记。

- **目的**：按月输出损益表、资产负债表、现金流量表，数据源于 `mgm_finance_summary`。
- **操作步骤**：
  1. 进入「财务报表」→ 选择公司与月份 → 切换三个页签。

# 6. 电子化报税（VAT / CIT / IIT）

> 入口：「税务申报」页，内含 **VAT / CIT / IIT / 申报记录** 四个 Tab。

## 6.1 VAT 增值税申报（Tab 1）

- **目的**：按月（一般纳税人 13%）或按季（小规模 3%）计算应纳税额并生成申报表。
- **操作步骤**：
  1. 选择月份 → 点击**「算税」** —— 系统自动汇总当期销项/进项发票（`mgm_invoice_details`），计算应纳税额 = 销项 − 进项 + 进项转出 − 留抵。
  2. 查看**取数明细区** —— 销项/进项逐笔列出，可核对每张发票；小规模纳税人自动判定 30 万免征阈值。
  3. **栏位点击钻取** —— 算税结果表中「🔍 銷售額合計 / 銷項稅額 / 進項稅額（可抵扣）/ 上期留抵稅額」四个蓝色栏位可直接点击，弹窗显示对应发票明细（发票号/金额/税率/税额 + 合计）；小规模纳税人弹窗自动按 3% 征收率口径展示、进项显示「不可抵扣」，与算税结果保持一致。
  4. 如有特殊事项，在**调整区**录入「进项转出 / 留抵」—— 写入 `tax_vat_adjustments`，点击**重算**生效。
  5. 确认无误点击**「提交税局申报」** —— 生成受理号并写入 `vat_declarations` + `tax_submit_receipts`。
  6. 点击**勾稽核对**（`/api/tax/vat/reconcile`）—— 申报数 vs 账载发票合计比对，差异亮红。
- **税率来源**：一般纳税人税率与小规模征收率读取系统码表 `TAX_TYPE`（码值 `CIT` = 一般纳税人、`IIT` = 小规模纳税人，取 `value_number1`），管理员维护码值即可调整，无需改程序（服务端缓存 1 小时）。

## 6.2 CIT 企业所得税汇算（Tab 2）

- **目的**：年度汇算清缴，财报利润 ± 纳税调整 × 25%。
- **操作步骤**：
  1. 选择年度 → **算税** —— 自动取全年财报收入/成本/费用，计算应纳税所得额与应纳税额。
  2. 若审计调整与账面不同，在**人工覆盖区**录入调整后收入/成本（`tax_cit_inputs`），调整事项（招待费调增等）录入 `tax_cit_adjustments` → **重算**。
  3. 提交申报 —— 写入 `cit_annual_settlements` + 回执。
- **说明**：覆盖前/覆盖后双值留痕，供稽查举证。企业所得税税率读取码表 `TAX_TYPE` 中 `EIT` 的 `value_number1`（预设 25%），码表无值时回退 25%。

## 6.3 IIT 个人所得税（Tab 3）

- **目的**：工资按月累计预扣；年终奖支持单独/并入双通道自动选优。
- **操作步骤**：
  1. 先维护**薪酬明细**（`payroll_details`）与**奖金明细**（`bonus_details`）—— 可逐笔录入或批量导入。
  2. 选择月份 → **算税** —— 系统按累计预扣法（7 级累进）逐人计算当月预扣税额。
  3. 年终奖月份：系统同时计算 **SEPARATE**（÷12 找月度税率）与 **COMBINED**（并入综合所得边际税额）两种结果，自动标注**节税更优方案**。
  4. 提交申报 —— 写入 `iit_withholding_batches` + `iit_withholding_details` + 回执。

## 6.4 申报记录（Tab 4）

- **目的**：集中查询历史申报与受理回执。
- **操作步骤**：
  1. 按税种/期间/状态筛选 —— 列表展示受理号、提交人、时间、金额。
  2. 点击行查看申报快照（提交时的完整计算结果 JSON）。
- **说明**：⚠️ 当前提交链路为**本地模拟受理**（未接真实税局 API），受理号格式与留档机制已就绪，对接后沿用。

# 7. 现金流预测（13 周 + 概率模拟）

## 7.1 13 周滚动预测

- **目的**：预测未来 13 周现金流入/流出，守住安全水位。
- **操作步骤**：
  1. 进入「现金流预测」—— 系统按在手 AR/AP、历史回款周期生成 13 周滚动预测表。
  2. 查看**水位线** —— 低于安全水位的周次红色警示。
  3. 调整假设（回款天数、付款计划）→ 重算，做 What-if 推演。

## 7.2 概率预测（Monte Carlo）

- **目的**：点估计只能给一个数字，概率预测回答「这个月现金不够用的可能性有多大」。
- **操作步骤**：
  1. 进入「现金预测」页 → 顶部模式切换选择 **Monte Carlo 概率带** —— 图表由单线变为 P10 / P50 / P90 区间带。
  2. 查看**概率风险卡** —— 展示未来 13 周内出现负现金的概率、最差周次与缺口金额。
  3. 切换回「点估计」可对比基础预测线，判断乐观/悲观差异。
- **说明**：数据来源 `/api/cash-forecast/monte-carlo`，采用 5000 次模拟（按历史回款波动抽样），仅覆盖已有数据的公司期间。

# 9. 业务单据（PO / SO / DN）

- **目的**：采购订单（PO）、销售订单（SO）、送货单（DN）线上化，作为发票与凭证的业务源头。
- **操作步骤**：

# 10. 批次管线（7 步数据加工）

- **目的**：将 ERP 原始数据加工为管理报表可用数据，一键顺序执行 7 个步骤。
- **操作步骤**：
  1. 进入「批次管线」—— 页面展示 7 个步骤卡片（抽取 → 清洗 → 转换 → 汇总 …）。
  2. 点击**「全部执行」** —— 步骤按依赖顺序串行运行，每步实时显示进度与耗时。
  3. 任一步骤失败即中断并红标 —— 点击该卡片查看错误日志，修复后可**单步重跑**。
- **说明**：管线具备幂等设计（先清本次再重建），重跑不产生重复数据。

# 11. 第三方资料整合（Excel / SQL）

> 入口：「资料整合」页，内含 **5 个 Tab**：📊 Excel 导入 / 🔌 SQL 线上整合 / ⏰ 批次作业 / 🗄️ 数据源 / 📜 执行日志，整页支持简/繁/英三语。

## 11.1 Excel 导入（Tab 1）

- **目的**：业务人员自助把 Excel 数据并入系统，无需 IT 写脚本。
- **前置条件**：明确要写入的目标资料表；建议先下载系统模板，避免栏位名不符。
- **操作步骤**：
  1. 选择**目标资料表** —— 下拉列出 `ermm_db` 内全部表（含中文表注释）。
  2. 点击**「下载本表模板」** —— 系统按该表栏位动态生成 xlsx 表头（也可点「下载全表模板」取得总模板）。
  3. 上传 `.xlsx`（单档 ≤ 20MB）→ 选择 **Sheet** —— 系统用 ExcelJS 解析并预览前 5 行与总行数。
  4. **栏位映射** —— 同名栏位自动匹配，可手动调整；系统实时校验目标栏位是否存在于白名单（防注入）。
  5. 选择**写入模式**（INSERT 新增 / UPSERT 依唯一键更新）→ 点击执行。
  6. 执行结果写入 `intg_log`，可在「执行日志」Tab 查看新增/更新/失败行数。
- **说明**：日期、千分位数字、空值会自动清洗；每批 200 行写入，失败行不影响已成功批次。

## 11.2 SQL 线上整合（Tab 2）

- **目的**：直接从第三方 MySQL 库抽取数据，或先预览再决定是否落库。
- **前置条件**：已在「数据源」Tab 建好第三方连线（或本页新建并测试通过）。
- **操作步骤**：
  1. 选择**数据源** → 输入一条 **SELECT** 查询 → 点击**测试读取**预览结果（最多 100 行，前端默认取 50 行）。
  2. 选择**目标资料表**并完成**栏位映射**（可沿用预设唯一键）。
  3. 点击**立即执行**写入本地表；或点**存为批次作业**，转由排程自动执行。
- **说明**：仅允许单条 SELECT、禁止多语句，系统自动包成子查询并强制 `LIMIT`，第三方库只读访问。

## 11.3 批次作业（Tab 3）

- **目的**：把 SQL 整合配置保存为可重复执行的作业，按排程自动同步。
- **操作步骤**：
  1. 查看**作业清单** —— 显示数据源、目标表、排程、启用状态与上次执行结果。
  2. **启用 / 停用** —— 停用后不再被排程触发，配置保留。
  3. **编辑** —— 调整 SQL、映射、排程（`daily HH:mm` 每日定时或 `every Nm` 每 N 分钟）。
  4. **立即执行** —— 手动跑一次（Online）。
  5. **失败重试** —— 上次状态为 `FAIL` 的作业会显示「重试」按钮，一键重跑。
- **说明**：排程器每分钟 tick，具备防重入（同一作业同一时刻只跑一份）与防重复触发机制。

## 11.4 数据源（Tab 4）

- **目的**：集中管理第三方 MySQL 连线。
- **操作步骤**：
  1. **新增数据源** —— 填名称、主机、端口、库名、账号、密码。
  2. **测试连接** —— 保存前可先预检；保存后也可随时再测。
  3. **编辑 / 删除** —— 删除时系统同步关闭并释放该数据源的连接池。
- **说明**：每个数据源的连接池按 `sourceId` 缓存复用，避免反复握手。

## 11.5 执行日志（Tab 5）

- **目的**：追溯每次导入/同步的结果，快速定位失败原因。
- **操作步骤**：
  1. 进入「执行日志」—— 默认显示最近 100 条记录。
  2. 按**状态**（SUCCESS / FAIL / RUNNING）或**通道**（SQL / Excel）筛选。
  3. 查看每条的作业名、触发方式（排程 / 手动 / Excel）、目标表、总行数、新增/更新/失败行数、耗时与错误信息。
  4. 点击**导出 CSV** —— 将当前筛选结果导出（UTF-8 BOM，Excel 直接打开不乱码）。

# 12. 财务预警 / KPI 查询（YG001~YG004）

> 菜单分组「財務預警 / KPI 查詢」，包含 YG001~YG004 四个页面，构成「指标定义 → 预警监控 → 异常甄别 → 趋势预测」的完整风控闭环。

## 12.1 YG001 KPI 预警指标

- **目的**：集中查看所有 KPI 的当期预警状态，让管理者一眼看出「哪些指标亮红灯」。
- **功能**：展示各 KPI 的当期值、门槛值、灯号（绿/黄/红），数据来源于预警引擎对 5 条预警规则的扫描结果（工作日 09:30 / 16:30 由 node-cron 自动执行）。
- **操作步骤**：
  1. 进入「YG001 KPI 预警指标」—— 列表按灯号排序，红灯指标排最前。
  2. 查看每项 KPI 的**当期值 vs 门槛值** —— 判断是否真实异常或阈值设置过严。
  3. 点击红灯指标 —— 联动跳转 YG003 报表异常甄别，查看 Top3 原因。
- **说明**：触发预警时系统同时以邮件（nodemailer）通知责任人，无需人工盯屏。

## 12.2 YG002 KPI 指标管理

- **目的**：维护 KPI 定义与预警阈值，让预警规则随经营策略调整。
- **功能**：KPI 的新增/编辑/停用——定义指标名称、计算公式、取数来源、门槛值、责任人与通知方式。
- **操作步骤**：
  1. 进入「YG002 KPI 指标管理」→ **新增指标** —— 填名称、公式、门槛（如毛利率下限 30%）。
  2. **编辑**既有指标 —— 调整阈值或责任人；修改即时生效于下一次扫描。
  3. **停用**不再适用的指标 —— 保留历史数据但不再扫描。
- **前置条件**：高阶主管或管理员权限。
- **说明**：阈值改得太松会漏警、太严会滥警，建议参考过去 6 个月实际波动区间设定。

## 12.3 YG003 报表异常甄别

- **目的**：指标异常时自动定位原因，回答「为什么超标、该找谁」。
- **功能**：对异常 KPI 自动下钻分析，输出 Top3 原因（维度归属、影响量化、改善建议），含 Z-Score 评分说明。
- **操作步骤**：
  1. 进入「YG003 报表异常甄别」（或从 YG001 / 仪表板红灯 KPI 点入）。
  2. 查看**当期值 / 门槛 / 较上期变化** —— 确认异常幅度。
  3. 阅读 **Top3 原因卡片** —— 每张卡含维度、描述、影响金额、改善建议。
  4. 按建议分派改善行动，次月同一页面验证异常是否消除。
- **说明**：数据来源 `/api/diagnosis/kpi`；建议由规则引擎产出，重大异常仍需人工复核。

## 12.4 YG004 预测模型分析

- **目的**：基于历史数据预测未来 3 / 6 / 12 个月经营趋势，支撑事前决策。
- **功能**：对收入、成本、利润等核心指标做趋势外推，展示预测曲线与置信区间。
- **操作步骤**：
  1. 进入「YG004 预测模型分析」→ 选择指标与预测期间（3 / 6 / 12 个月）。
  2. 查看**预测曲线图** —— 历史实线与预测虚线对比，拐点一目了然。
  3. 结合 YG001 预警结果 —— 若预测下行且当期已亮黄灯，提前启动应对预案。
- **说明**：数据来源 `/api/forecast`；预测基于历史趋势，突发市场变化需人工修正判断。

# 13. 系统管理与个人设置

## 13.1 用户管理（管理员）

1. 「用户管理」→ 新增/编辑用户 —— 设置工号、姓名、部门、**角色**（员工/部门主管/高阶主管/管理员）与 admin 标识。
2. 重置密码、停用账号；登录日志（`login_user_record`）可查。

## 13.2 系统码维护

- **目的**：集中维护全站下拉选项与业务参数，改配置不改代码。
- **操作步骤**：
  1. 「系统管理」→「系统码维护」—— 左侧按 `code_type` 分类，右侧列出码值。
  2. **新增 / 编辑码值** —— 填写 `code_value`（码值）、`value_description`（显示名称）、`value_number1~3`（数值型参数，如税率/汇率）、启用标志与排序。
  3. **停用 / 删除** —— 停用后该码值不再出现在业务下拉中，历史数据不受影响。
  4. 查看 `schema_migrations` 可确认数据库迁移版本。
- **常用码表**：`BUSINESS_ID`（公司账套 HM/SZ/HN）、`TAX_TYPE`（VAT/CIT/IIT/EIT 税率）、`CURRENCY`（汇率）、`WK_TYPE`（工作类型）、`USER_ROLE`（角色）等。
- **生效时间**：前端刷新页面后读取新码值；服务端缓存 TTL 为 1 小时，税率等参数最迟 1 小时内生效（重启服务可立即生效）。调整税率后如马上算税，请先重启服务或等待缓存过期。

# 14. 智能化功能（AI 赋能）

> 本章 5 个功能构成系统的「智能层」：**知识问答、自动摘要、催收排序、数据体检、概率预测**。
> 全部功能均为**只读分析**，不会自动修改账务数据；如需修正请回到对应业务页面操作。

## 14.1 AI 智能问答（RAG）

- **目的**：用自然语言提问（如「本月毛利率为什么下降」「发票丢了怎么补」），系统检索内部知识库后给出有依据的回答，免去翻文档。
- **前置条件**：已登录；知识库由管理员维护（`ermm_knowledge`，当前 41 条 / 6 个分类：年度 / 政策 / 税务 / 基准 / 数据字典）。
- **操作步骤**：
  1. 侧边栏「经营决策」→ **AI 问答** —— 进入对话界面。
  2. 在输入框提问，或点击页面下方的**建议问题**（系统按当期数据动态生成）。
  3. 回答下方展示**引用来源**（命中的知识条目），可点开核对原文；若知识库无匹配，会明确告知「未找到依据」并记入未命中日志。
  4. 左侧可查看**历史会话**，按会话继续追问（多轮上下文保留）。
- **说明**：后端为 `/api/aiqa/ask`；检索采用 n-gram 关键词滑窗 + 分类加权（税务 ×1.5 / 数据字典 ×1.3 / 政策 ×1.2 / 基准 ×1.0 / 年度 ×0.8）。回答仅供决策参考，涉及金额以报表为准。

## 14.2 AR 智能催收（应收优先级排序）

- **目的**：把手上一堆应收账款按「该先催谁」排序，把催收精力放在最该催的单据上。
- **前置条件**：`mgm_invoice_details` 中存在 `TX_type='AR'` 的发票明细（含账龄天数）。
- **操作步骤**：
  1. 侧边栏「日常作业」→ **AR 智能催收** —— 顶部显示各风险等级的笔数与金额概览。
  2. 查看**催收清单** —— 每条按综合评分排序，展示账龄天数、逾期天数、金额、客户与等级灯号。
  3. 按灯号分层处理：
     - 🔴 **紧急**（评分 ≥ 70）—— 当日联系，必要时暂停发货
     - 🟠 **高优先**（50~70）—— 本周内跟进
     - 🟡 **常规**（30~50）—— 按常规节奏提醒
     - 🟢 **正常**（< 30）—— 无需主动催收
  4. 切换公司（HM / SZ / HN）查看各账套的催收清单。
- **说明**：评分 = 账龄天数 40% + 逾期天数 30% + 金额规模 15% + 风险综合 10% + 单笔占比 5%，数据来源 `/api/ar-smart/collections`；清单只做排序建议，不自动发送催收函。

## 14.3 数据质量自动扫描

- **目的**：上线前一键体检，提前发现「报表数字不对」的根因（脏数据 / 缺失 / 重复 / 逻辑冲突），而不是等出报表才发现。
- **前置条件**：无，任意登录用户可执行扫描。
- **操作步骤**：
  1. 侧边栏「日常作业」→ **数据质量扫描** —— 点击**「开始扫描」**。
  2. 扫描约数十毫秒返回，页面按 **7 大类**展示结果：
     - 财务摘要（6 项）· 发票（5 项）· 银行贷款（3 项）· 现金（1 项）· 预测（2 项）· 勾稽（1 项）· 数据表健康度（8 张核心表）
  3. **红色问题项**为高风险（如报表不平衡、金额为空、重复单据），黄色为提示项；点击问题卡片可查看受影响的记录数与样例。
  4. 按问题类型分别修正：数据缺失 → 补录；重复 → 在业务页面作废；金额异常 → 核对源单据后由管理员修正。
- **说明**：接口 `/api/data-quality/scan`；当前版本为**只扫描不自动修复**，修复仍需人工确认，避免误改历史账。

## 14.4 系统文件（管理员专用）

- **目的**：随时查阅系统的架构说明与数据表关系，不必回开发环境找文件。
- **前置条件**：**admin = Yes** 的账号（如 `rocky`）。普通账号点击会被拦截。
- **操作步骤**：
  1. 侧边栏最下方**「系统文件」**分组，含两项：
     - 🗺️ **系统架构与流程图** —— 技术栈、API 模块地图、5 大核心数据流程
     - 🗄️ **模块数据表关系图** —— 表总览、ER 图、模块 × 数据表对照、索引与迁移顺序
  2. 点击后在新标签页打开文档页面。
  3. 非管理员点击 —— 页面右下角弹出红色提示「**你的权限不能使用这个模块功能**」，不打开文档。
- **说明**：文档由系统 3008 端口直接提供（`/docs/architecture`、`/docs/data-model`）；也可从左上角 🏢 ERMM 标志打开系统架构图。
