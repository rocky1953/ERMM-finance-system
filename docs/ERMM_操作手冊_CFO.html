ERMM 操作手冊 — CFO

月度结账七步 · 现金预测 · AR 催收 · 数据质检 · 报税 ｜ 由 Markdown 自動產生（唯讀文件）

适用角色：CFO（财务长 / 财务主管）｜适用版本：v4.0（2026-11-16） 系统地址：http://localhost:3008 ｜建议浏览器：Chrome / Edge 本手册覆盖你日常真正要操作的模块：看数、算账、报税、管现金、催收、质检、费用与付款审批。 本版新增：费用报销与借支核销（CFO-01）／付款申请·排程·银行回单·AR·AP 核销（CFO-02）／审批中心／合同主档与三单匹配联动（CTO-05）／指标中心统一盈利口径（CTO-06）。

CFO 是系统的主要深度使用者：既要看结果（报表），也要管过程（入账、报税、现金、催收、费用与付款），还要保证数据可信（质量扫描）。系统里 68 个入口中，约 36 个与你的职责直接相关。

二、登录与全局操作

  • 登录：http://localhost:3008 → 账号密码 → 仪表板。
  • 公司切换（HM / SZ / HN）：所有页面按 bu_no 取数，切公司即切账套。
  • 月份选择（YYYY-MM）：报表、日报、报税的期间口径。
  • 语言切换：简 / 繁 / 英。
  • 左上角 🏢 ERMM：打开系统架构图。

三、月度结账标准流程（按顺序执行）

① 数据质检（数据质量扫描）→ ② 财务摘要核对 → ③ 三大报表出表
→ ④ 风险预警处理 → ⑤ 财务入账/凭证 → ⑥ 电子化报税 → ⑦ 合并报表
→ ⑧ 费用报销 / 付款单据结清（审批、拨付、回单、核销）

⑧ 贯穿全月：报销与付款是日常动作，但月结前必须把已通过的款付完、回单登记完、核销做完，否则费用与应付余额对不上账。

3.1 ① 数据质量扫描（🛠️ 日常作业组）

  • 目的：出报表前先确认底层数据没有脏、缺、重、矛盾。
  • 操作：
    1. 侧边栏「日常作业 · 工作日报」→ 数据质量扫描。
    2. 点击 「开始扫描」，数十毫秒返回。
    3. 按 7 大类 查看结果：财务摘要 6 项 / 发票 5 项 / 银行贷款 3 项 / 现金 1 项 / 预测 2 项 / 勾稽 1 项 / 数据表健康度 8 张表。
    4. 🔴 红色 = 高风险（报表不平衡、金额为空、重复单据），必须处理；🟡 黄色 = 提示项，可择期处理。
    5. 点问题卡片可看受影响记录数与样例，回到对应业务页修正。
  • 注意：当前版本只扫描不自动修复，修复需人工确认，避免误改历史账。

3.2 ② 财务摘要核对（📋 财务分析组）

  • 操作：进入「财务摘要」→ 选公司与月份 → 核对收入、成本、费用、利润、资产、负债六组关键数。
  • 核对要点：与「三大报表」交叉比对；与上月环比看异常跳变。

3.3 ③ 三大报表（📈）

  • 操作：进入「三大报表」→ 切换资产负债表 / 损益表 / 现金流量表 → 选期间。
  • 校验标准：资产负债表必须平衡（系统内 108 个月已全部平衡）；出现不平衡先回 3.1 质检。
  • 导出：页面支持导出，用于对外报送或归档。

3.4 ④ 风险预警（⚠️）

  • 操作：进入「风险预警」→ 查看 5 套模型：Z-Score / Z2 / Z3 / BZ 破产概率 / JZ 营运能力。
  • 判断：灯号红色优先处理；Z-Score 卡片可查看评分公式与区间。
  • 联动：预警项可转「行动追踪」，指派责任人。

3.5 ⑤ 财务入账 / 凭证（📒）

  • 操作：进入「财务入账／报税」→ 按期间筛选待入账单据 → 核对后入账/生成凭证。
  • 注意：入账动作影响报表数字，入账前务必先跑一次数据质量扫描；已入账凭证的更正走冲销，不直接改数。

3.6 ⑥ 电子化报税（🧮）

  • 操作（三种税分四个页签）：
    1. VAT 增值税：选期间 → 取数算税 → 核对销项/进项 → 提交（本地模拟受理，返回受理号与状态）。
    2. CIT 企业所得税：录入/确认收入成本参数（支持人工覆盖）→ 算税 → 提交。
    3. IIT 个人所得税：导入薪资明细（含年终奖单独计税）→ 计算 → 提交。
    4. 录入维护：VAT 调整、CIT 参数、薪资、年终奖的原始录入。
  • 注意：提交为本地模拟受理，不产生真实税局效力；申报记录全程留痕（tax_submit_receipts）。

3.7 ⑦ 合并报表（📋）

  • 操作：选期间 → 查看合并三大报表；系统自动抵销内部交易。
  • 注意：合并口径依赖各公司当月数据齐全，缺一家会导致结果失真 —— 先确认三家都已跑完批次。

四、现金管理（💧 + 🎯）

4.1 现金预测（13 周 + 概率）

  • 操作：
    1. 「经营决策」→ 现金预测 → 默认 13 周滚动预测。
    2. 切换 Monte Carlo 概率模式 → P10 / P50 / P90 区间带 + 负现金概率。
    3. 调整假设（回款天数、付款计划）→ 重算，做 What-if。
  • 判断：安全水位 = 周均流出 ×3（下限 300 万），跌破即标红；概率 >30% 需提前安排融资或压支出。

4.2 AR 智能催收（🎯）

  • 目的：应收款按「该先催谁」自动排序，避免凭感觉。
  • 操作：
    1. 「日常作业」→ AR 智能催收 → 顶部看四个风险等级笔数与金额。
    2. 清单按综合评分排序，显示账龄、逾期天数、金额、客户、等级灯号。
    3. 按灯号处理：
      • 🔴 紧急（≥70）：当日联系，必要时暂停发货
      • 🟠 高优先（50~70）：本周内跟进
      • 🟡 常规（30~50）：常规提醒
      • 🟢 正常（<30）：无需主动催收
    4. 切换公司查看各账套清单。
  • 评分公式：账龄 40% + 逾期 30% + 金额规模 15% + 风险综合 10% + 单笔占比 5%。
  • 注意：清单是建议排序，系统不自动发催收函。

4.3 费用报销与借支核销（🧾 CFO-01）

入口：日常作业 · 工作日报 → 费用报销（页签：我的报销 / 待我审批 / 借支管理 / 全部报销）。

费用报销

  • 目的：把纸质报销单搬到线上，审批与付款状态可查。
  • 新建流程：
    1. 点「新增报销」→ 填事由、费用类型（差旅 / 交通 / 业务招待 / 办公 / 其他）、公司、备注。
    2. 加明细行：费用日期、费用类别、说明、金额、发票号、税额；合计自动汇总。
    3. 保存草稿（状态 DRAFT）或保存并提交（状态 PENDING，进入审批流）。
    4. 提交后生成单号 BX+日期+序号，可在「我的报销」查看进度。
  • 审批：审批人在「待我审批」页签或「审批中心」处理，通过后状态 APPROVED；管理员再点「标记付款」→ PAID。
  • 撤回：审批中（PENDING）本人可撤回，状态变 CANCELLED；被驳回（REJECTED）可修改后重新提交。

借支与核销

  • 目的：员工出差 / 采购先借钱，回来凭票核销，余额自动结清。
  • 借支申请：借支管理页签 → 新增 → 选类型（差旅借支 / 一般借支 / 备用金）、金额、用途 → 提交审批；单号 JK+YYYYMMDD+序号。
  • 拨付：审批通过（APPROVED）后，仅管理员可执行「标记已拨付」→ PAID。
  • 核销：出差结束在借支行点「核销」→ 填核销金额与说明；核销金额不得超过剩余余额；余额归零自动 SETTLED（已结清）。
  • 注意：借支余额是硬约束，多次核销累计扣减；已结清的借支不能再核销。

4.4 付款申请 / 付款排程 / 银行回单 / AR·AP 核销（💳 CFO-02）

入口：日常作业 → 付款申请（页签：我的申请 / 待我审批 / 全部 / 付款排程）。

付款申请

  1. 新增 → 填供应商、事由、公司、金额，加付款明细行 → 保存或提交。
  2. 单号 PK+YYYYMM，状态：DRAFT → PENDING → APPROVED → PAID（或 REJECTED / CANCELLED）。
  3. 审批通过后，才进入付款执行环节。

付款排程

  • 目的：把「这个月要付哪些钱」排到日历上，提前看资金压力。
  • 操作：切到「付款排程」页签 → 按月汇总待付金额 → 逐笔设置计划付款日（planned_pay_date）→ 保存。
  • 用法：结合「现金预测」13 周曲线，把大额付款错开现金低点。

银行回单登记

  • 操作：实际付款后，在已通过（APPROVED）的付款申请上点「登记回单」→ 填回单号（必填）、回单日期、实付金额 → 保存。
  • 结果：状态自动 APPROVED → PAID，账实同步；回单号与实付金额留档备查。

AR / AP 核销

  • 目的：确认「这笔付款到底核掉哪几张发票」，避免重复付款与漏核销。
  • 操作：
    1. 切到「核销」页签 → 选择付款申请 → 点「选择核销来源」。
    2. 系统列出可核销发票（mgm_invoice_details 中 sub_amt > payment 的未核销款），勾选并填核销金额。
    3. 支持部分核销：累计核销金额 ≥ 发票总额 → 状态 WRITTEN（全额）；否则 PARTIAL（部分）。
    4. 核销错误可「撤销」，撤销后重新核销。
  • 注意：核销金额不得大于发票未核销余额；跨账套不可混核。

4.5 审批中心（✅）

  • 入口：日常作业 → 审批中心（页签：待我审批 / 我发起的 / 流程设定）。
  • 处理待办：进入「待我审批」→ 点单据查看明细（金额、明细行、事由）→ 通过 / 驳回（驳回需填意见）。
  • 看我发起的：跟踪自己提交的单据走到哪一关、卡在谁那里。
  • 流程设定（仅管理员）：维护 wf_process 的签核层级（steps_json），可按费用报销 / 借支 / 付款申请分别设定审批人与顺序。
  • 要点：审批动作写入 wf_log（审批人、意见、时间），全流程可追溯；同一张单只有一个进行中的实例。

4.6 月结关账（📅）

  • 入口：经营决策 → 月结关账。
  • 目的：把月结从「口头催办」变成「任务清单 + 时间点」，谁没做完一目了然。
  • 操作：
    1. 选公司与月份 → 系统按关账日历生成任务清单（closing_calendar / closing_task / closing_task_instance）。
    2. 逐项执行：数据质检、计提、摊销、结转、对账、报表出表。
    3. 每项任务标记完成（记录负责人与时间）；全部完成后执行关账，关账后当期不再允许改数。
  • 注意：关账前必须先把费用报销、付款、回单、核销处理完（见 3.1 第 ⑧ 步）；需要调整时走「反关账」，须高阶权限并留痕。

4.7 外汇曝险与避险（🌐）

  • 入口：经营决策 → 外汇曝险。
  • 用途：按币别汇总未结外汇敞口（应收 / 应付 / 借款），并登记已做的避险工具（远期 / 期权）。
  • 操作：
    1. 看敞口表：币别、敞口金额、折本币金额、已避险比例。
    2. 「避险登记」：录入避险工具类型、金额、汇率、到期日（fx_hedge）。
    3. 看「覆盖率」：已避险 / 总敞口；覆盖率低且本币波动大时，考虑补做避险。
  • 注意：本模块为管理口径，不自动生成会计分录入账；实际交割仍走资金与银行模块。

4.8 税务筹划与税务合规（🧾）

  • 入口：财务分析·税务申报 → 税务筹划、税务合规。
  • 税务筹划：查看适用税务优惠政策（tax_preference）与可抵扣项（vat_deductions），评估节税空间；筹划方案不直接改申报数据，需人工确认后录入。
  • 税务合规：
    1. 法规清单（tax_regulation）与合规事项（tax_compliance_item）：按税种、期间查看应办事项。
    2. 申报任务（tax_filing_task）：显示截止日与状态，逾期标红。
    3. 完成后在任务上标记办结，形成「法规 → 事项 → 任务」的合规证据链。
  • 用法：每月申报前先看任务清单，避免漏报；季度做一次优惠政策复核。

4.9 资金流动性与投资（💧）

  • 入口：经营决策 → 资金流动性、投资管理。
  • 资金流动性：按周 / 月看现金计划（cash_plan_item）与实际流入流出，评估流动性缺口与融资需求。
  • 投资管理：登记投资项目、预算与实际现金流（investment_project / investment_budget / investment_cashflow），看回收期与 IRR 口径。
  • 用法：大额付款排程前先看流动性缺口；投资项目立项前用本模块做现金流测算，避免与现金预测脱节。

5.1 滚动预算与三表联动（🔄）

  • 入口：经营决策 → 滚动预算。
  • 默认口径：以财务汇总最新实际月为基准，取最近 3 个月平均推导收入与费用结构；无保存假设时按实际数自动推导。
  • 操作：
    1. 选择公司，确认「假设参数」：收入增长率、销售成本率、所得税率、应收/应付/存货天数、资本支出、每月还本。
    2. 保存后，损益表 → 资产负债表 → 现金流量表按同一套假设联动重算，并做「资产 = 负债 + 权益」勾稽。
    3. 切换到「13 周现金」查看滚动现金预测与安全水位。
  • 关注点：最低现金余额出现的月份、期末现金、三表平衡差（应接近 0）。预算属于假设驱动，改任一假设都会联动影响三张表，评审前先固定假设版本。

5.2 多维盈利（💹）

  • 入口：经营决策 → 多维盈利。
  • 用途：按客户、产品、区域、渠道等维度拆解收入、毛利与净利，识别「高收入低毛利」的客户/产品。
  • 操作：选公司与期间 → 切换分析维度 → 看贡献排名与毛利率分布；导出结论用于定价与资源调整。
  • 注意：维度归集依赖原始单据字段完整性；若某维度出现大量「未分类」，先让 COO/业务侧补主档。

5.3 库存周转与呆滞（📦）

  • 入口：经营决策 → 库存周转。
  • 核心指标：存货周转率 = 近 12 个月销售成本 ÷ 平均存货价值；周转天数 DSI = 365 ÷ 周转率。
  • 库龄：取自库存日快照，默认选择料件最完整的最近日期，可在页头切换快照；分 0-30 / 31-90 / 91-180 / >180 天四档。
  • 呆滞：库龄 > 90 天即进入呆滞清单，按金额与严重度排序；可「下发处理」（降价促销/退货/报废/转用/暂停采购/调拨），由 COO/仓库执行。
  • 补货建议：目标覆盖天数可调，补货点 = 交期 + 安全天数；无销售数据的料件以采购量近似需求。
  • 财务用法：每月审「呆滞金额占比 + 减值准备」，与库存减值模块交叉核对；对超储料件推动暂缓采购。

5.4 合同主档与三单匹配联动（📝 CTO-05 新增）

  • 入口：ERP 原始单据 → 合同主档。
  • 目的：把合同信息纳入三单匹配（PO / 到货 / 发票），避免「采购价与合同价对不上还在付款」。
  • 合同主档结构：28 栏（ermm_contract），核心字段：合同编号 / 甲方 / 乙方 / 合同金额 / 币种 / 签约日 / 到期日 / 合同状态 / 关联 PO 编号 / 付款条款。
  • 三单匹配联动：
    1. 以前三单只比 PO / 到货 / 发票的数量和单价。
    2. 现在多一层 合同价校验：PO 的单价 vs 合同约定价，差异超过阈值（可配置）直接标红。
    3. 合同 → 采购 → 到货 → 发票 → 付款，全链路可追溯，付款前必须确认合同已关联且价格无差异。
  • 财务用法：
    • 月结前跑一次三单匹配，把合同价格差异的单拎出来处理。
    • 新供应商付款前，先确认有没有合同；没合同的让采购补签再走流程。
    • 合同到期预警：到期前 30 天系统自动提醒续签。
  • 注意：合同主档系统已从 ermm_erp_po 自动种了 10 笔示范数据；正式使用前请让 CTO 跑一次清理脚本把示范数据删掉。

5.5 指标中心统一盈利口径（📊 CTO-06 新增）

  • 入口：你不需要直接操作这个模块 — 它是底层引擎（services/metricCenter.js + cams_metric_def 23 指标 7 类别），被仪表板、滚动预算、多维盈利、库存周转统一调用。
  • 对你的影响：
    1. 毛利率口径统一：以前仪表板毛利 = 收入 - 发票成本，多维盈利毛利 = 收入 - 财务摘要成本，偶尔差几个点。现在都从指标中心取，公式唯一。
    2. ROE 计算透明：ROE = 净利润 / 平均股东权益（权益取期初 + 期末 / 2），公式在 cams_metric_def 里是公开的，任何人都可以查。
    3. DSI / DSO / DPO 同源：存货周转天数 = 365 × 平均存货 / 销售成本，应收周转天数 = 365 × 平均应收 / 收入，统一从财务摘要取数，不再各算各的。
  • 财务用法：
    • 有人问「为什么仪表板 ROE 和我算的不一样？」→ 让对方去指标中心看公式，确认自己的公式有没有差。
    • 新增指标口径变更 → 让 CTO 改 cams_metric_def + 更新 metricCenter.js，不要在多个 Excel 里各改一遍。

六、每周 / 每月 / 每季动作

  • 每日：看仪表板 AI 摘要 → AR 智能催收清单（🔴 当天处理）。
  • 每周：现金预测看 13 周缺口 → 更新收付款计划 → 预警处理。
  • 每月：按第三章 ①~⑦ 顺序完成结账；报税前跑一次数据质量扫描；看一次滚动预算与库存周转（呆滞占比、DSI）。
  • 每季：预算执行复盘 + 风险模型复核 + 同业标杆对比。
